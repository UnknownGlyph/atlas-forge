## 2. 构建、运行与检查

### 2.1 环境

- Windows，Rust 1.99（`rustup` 默认 MSVC 工具链），Visual Studio 的 C++ 生成工具。
- **所有 cargo 命令都可以通过 `tools\cargo-msvc.cmd`**：rustc 能自己找到已注册的 Visual Studio（或其生成工具）时，它就是普通的 `cargo`；找不到时（Visual Studio 没有在 vswhere 中注册，报错找不到 `link.exe`），把 `vcvars64.bat` 的完整路径写进环境变量 `VCVARS64`，或写进 `tools\local.cmd`（不进 git）：`set "VCVARS64=…\VC\Auxiliary\Build\vcvars64.bat"`。
- 从 Git Bash 调用时写成：`cmd //c "tools\\cargo-msvc.cmd build --release -p map_app 2>&1"`。

### 2.2 常用命令

| 目的 | 命令 |
|---|---|
| 构建应用 | `tools\cargo-msvc.cmd build --release -p map_app`，产物 `target\release\atlas.exe` |
| 全部检查（构建 + 测试 + clippy） | `tools\check.cmd`，结尾打印 `ALL CHECKS PASSED` |
| 再加长时间压力测试 | `tools\check.cmd soak`（32 种子 × 1500 步，数分钟） |
| 单个测试文件 | `tools\cargo-msvc.cmd test --release -p map_core --test curve` |
| 性能基准 | `tools\cargo-msvc.cmd run --release -p map_bench`（说明见 `docs/BENCHMARKS.md`） |
| 只读查询接口 | `target\release\atlas-query <世界.atlas \| --demo \| --test-world> [--request '<JSON>']` |
| MCP 服务器 | `target\release\atlas-mcp <世界.atlas>`（stdio；配置见 `docs/API.md`） |

注意：

- 测试一律用 `--release`（有些测试在 debug 下很慢）。
- **`cargo test` 不会重新生成 `atlas.exe`**。改了界面要单独 `build --release -p map_app`，并先关掉正在运行的 `atlas.exe`（否则链接时报"拒绝访问"）。
- clippy 现有约 60 条旧警告（`map_or` 可简化、类型复杂等），都不是错误；新代码尽量不增加。

| `ATLAS_SOAK_SEEDS` / `ATLAS_SOAK_STEPS` / `ATLAS_SOAK_ONLY` | 压力测试的种子数、每种子步数、只跑某个种子 |

## 4. 核心概念与数据模型

### 4.1 文档（`map_core::doc::Document`）

字段（都在 `doc.rs` 的 `pub struct Document`）：

- `topo`：拓扑。`faces` 里 `FaceId(0)` 是 `BACKGROUND`（外部的海或陆地）。面有 `kind`（陆地/水域）、外环与洞；边的 `left`/`right` 是两侧的面。
- `entities`：国家、省、城市、文化等。`kind`、`layer`（属于哪个分区层）、`parent`、存续期、颜色……
- **归属与年份**：`owner_base` + `owner_changes`（每个面的归属历史：某年起归谁），`kind_base` + `kind_changes`（某年起是陆地还是水域）；`year` 是当前查看的年份（`None` = 最新状态）；`owner` 是**当前年份的视图**，由 `refresh_owner()`（全部）或 `refresh_face_owner()`（一个面）从历史算出。两者必须遵守同样的规则（水域无主、实体不存续则无主）。
- `layers` / `active_layer`：分区层（政治、文化、宗教比例层……），每层有自己的归属记录；`POLITICAL` 是政治层。
- `fields` / `values`：数据字段与（可随年份变化的）数值。
- 绘制要素（都是"版式"，不随年份变；符号与区域可设显示年份范围）：`rivers`（河流与线路，`LineFeature.route` 有值即线路）、`annotations`（地图文字）、`symbols`、`areas`（斜线区域）。键都是 `LineId`，从 `topo.alloc()` 取号，与拓扑共用一个计数器。
- `locked`：锁定的要素；`groups` / `group_of`：要素图层；`curves`：曲线；`styles` / `style_of` / `swatches`：命名样式、要素与样式的关联、色板。**这些都是按要素 id 放在文档上的旁表，而不是加在要素结构里**——要素结构有几十处直接构造（`LineFeature { … }`），加字段要改遍全工程，旁表则对旧文件、旧代码都透明。新增同类属性时沿用这个做法。
- `style`（含国家名称字体 `label_font`/`label_bold`）/ `theme` / `layouts` / `underlays` / `meta`。地图文字 `Annotation` 有自己的 `font`/`bold`。

新增字段必须：`#[serde(default)]`（旧工程读得出）、在 `Document::new()` 里初始化、考虑撤销（文档整体快照，自动支持）、考虑 `features` 被删除时清理旁表（见 `arrange::delete_features`）。

### 4.2 修改与撤销

- 界面里的一切修改都走 `App::edit(label, |doc| …)`：成功则成为一步撤销，失败则文档原样恢复并在状态栏报错。它还负责把新增的要素放进"当前图层"。
- 拖动这类持续的修改用 `begin_pending(label)` … 每帧直接改 `self.doc` 并设 `pending.changed = true` … `end_pending()`，整个拖动是一步撤销。
- 文档用 `imbl` 持久化映射，克隆是 O(1)，快照撤销几乎不占内存；`History` 有步数与内存上限。

### 4.3 绘制与渲染

- 地图底图（面填充、海岸/国界线、河流）由 GPU 绘制，`map_render::tess::SceneCache` 按 `ChangeSet` 局部更新；状态栏"更新 x ms"即这一步。
- 绘制要素（线路、区域、文字、符号、图层里的河流）和所有交互叠加（选中框、草稿、锚点）由 egui 画笔在 GPU 图层之上绘制（`view.rs::draw_overlays`）。
- 导出不读屏幕：`map_io::scene::build_scene` 从文档重新生成矢量场景，PNG 与 SVG 共用。
- **所有线条在经纬度平面上是直线段**（展开经度后线性插值），平面图与球面都按这个约定画。曲线也是在这个平面里的贝塞尔曲线。

### 4.4 时间（年份）语义

- 选定年份时的编辑默认"从该年起生效"，更早的年份不变；不选年份时修改所有年份共用的状态。
- 原则：**优先保证语义一致、兼容旧项目、不错误覆盖历史数据；不要为了增加配置而让普通操作复杂。** 没有年份的地图必须照常工作。
- 详细规则见 `ARCHITECTURE.md` 的 ADR-7 与 M3、M4 各步。

### 4.5 叠加运算（画陆地等）

`overlay::apply(doc, ring, intent)`：只重建被多边形碰到的陆地面，再拼回未动的拓扑（`apply_local`）；遇到无法安全拼接的情况（触及湖泊、围出内海……）退回整体重建（`apply_whole`），报告里写明原因。重建都经过 `repair::repair_strip`（条带坐标，日界线两侧分开）→ `build::build_with`。日界线、极点、内海、细缝都有专门处理和测试。

### 4.6 选择、图层、曲线、样式（M6–M7 新增的四个模型）

- **选择**（`select_ui.rs`）：`App::picked`（选择工具下选中的要素集合）加上各工具面板正在编辑的那一个，合起来是 `selection()`。按下时的修饰键记在 `press_mods`（快速单击时松开那一帧 Shift 可能已经放开）。
- **图层**（`stack.rs`、`layers_ui.rs`）：不在任何图层的要素最先绘制、顺序与以前相同，然后各图层自下而上；隐藏的图层不绘制、不导出、不能拾取；锁定的不能选中。`Document::pickable(f)` 是"能否在地图上选中"的唯一判断。
- **曲线**（`curve.rs`、`curve_ui.rs`）：见 §10。要点：**曲线是源，要素的点是派生的**（`pts`/`ring` = `curve.flatten()`）；直接改点的操作必须调用 `Document::points_changed(id)`（把它变回普通线），移动、旋转、缩放、复制必须同时变换曲线并用 `set_curve` 重新细分。
- **样式**（`styles.rs`、`styles_ui.rs`）：见 §10。要点与曲线同一个思路：**外观仍存在要素自身的字段里**（线路的 `route`、区域的颜色与图案、文字的字号……），关联了样式的要素，其外观始终等于样式的外观；渲染、导出、查询都不用知道样式的存在。改样式用 `update_style`（写回全部关联要素）；界面每帧调用 `settle_styles()`：若某个关联要素的外观被它自己的面板改了，就把这个改动推给样式和其余关联要素（"改一个即改全部"；只想改一个先"脱离样式"）。没有关联样式的要素（包括所有旧工程的要素）就是"本地样式"，行为与以前完全相同。

### 4.7 动作层

`actions.rs` 的 `table()` 列出全部命令（名称、菜单、快捷键、说明）；`can()` 决定是否可用，`run()` 执行。菜单、快捷键、命令面板（Ctrl+K）、画布右键菜单、快捷键一览（F1）都从这张表生成。**新命令只需加一行并在 `can/run` 里处理**；表的自检测试会检查快捷键不重复、每个工具有动作且按键一致。

## 5. 必须一直成立的不变式

压力测试（`map_io/tests/soak.rs`）每一步都检查这些；新功能如果引入新的不变式，也要加进去。

1. `topo.validate()` 通过：边两侧不是同一个面、环闭合且方向正确、边界不相交……
2. 每个面面积为正，各面之和不超过球面。
3. 年份视图 `owner` 等于完整刷新的结果；实体的 `parent` 亦然。
4. 水域无主；拥有土地的实体在该年存续；历史记录不引用不存在的面或实体。
5. 比例层每个面的份额之和不超过 100%。
6. 在某年做的修改不改变更早年份的任何面积（所有分区层）。
7. 保存再读取得到同一个世界；导出与标注不崩溃。
8. 撤销全部步骤回到初始世界。
9. 每条曲线都属于一条存在的线或区域，且该要素的点恰好是曲线的细分结果。
10. 每个样式关联都从一个存在的要素指向一个存在的样式，且该要素的外观等于样式的外观。

## 6. 约定与容易踩的坑

**代码与文件**

- 很多源文件是 **CRLF** 换行。用脚本改文件时先统一成 `\n`，改完再还原，否则字符串匹配会失败（这在开发中多次出现）。
- 注释与文档用中文写用户可见的内容，代码注释多为英文；界面文字全部中文。
- 新增 `Tool` 时要改：`view.rs` 的枚举、`ALL`（数组长度）、`key()`、`label()`、`help()`、`tool_input` 及其他 `match self.tool` 的分支；`toolbar_ui.rs` 的图标和分组分隔位置（`matches!(i, 1 | 6 | 8 | 15)`）；快捷键不能和动作表冲突（自检测试会报）。
- 新增文档字段见 §4.1。

**egui 0.37 的行为**

- Ctrl+C/X/V 以 `Event::Copy/Cut/Paste` 送达，不是按键事件（`select_ui::clipboard_events`）。
- 快速单击时，松开那一帧修饰键可能已经放开：用按下时记下的 `press_mods`。
- 面板里有一段会出现/消失时，**其后控件的 id 会变，键盘焦点会跳到别的控件**（曾导致回车删掉了 45 个要素）。会出现或消失的段落用 `ui.push_id(...)` 包起来，列表行用稳定的 id（如图层 id）。
- 文本框有焦点时，Ctrl+A/Z/Y 属于文本框，动作层已跳过它们（`text_chord`）。
- 界面字体里没有"✓""▾"等部分符号，会显示成方框；用文字或"…"（"▲▼"可以显示）。
- `ComboBox` 默认"点击任意处即关闭"：弹出层里有输入框时用 `.close_behavior(PopupCloseBehavior::CloseOnClickOutside)`，选中项后 `ui.close()`。
- 字体：每个用到的字体注册为独立的 `FontFamily::Name`，换字体集合要 `ctx.set_fonts`（重建字形图集），所以只在集合变化时做；界面字体缺字符时显示方框。
- 文字弯曲：`galley.rows[i].visuals.mesh` 的顶点相对于行（加 `rows[i].pos`），纹理坐标是字形图集的像素，要除以 `ctx.fonts(|f| f.font_image_size())`；每个字是 4 个顶点。图集会在一帧中途变大，所以先排版所有文字再读大小，变了就再画一帧（`label_ui`）。
- `double_clicked()` 在第二次单击的那一帧为真，同一帧 `clicked()` 也为真；第一次单击照常触发 `clicked()`。

**几何**

- 经度跨日界线：用 `lon_delta`/`unwrap_path` 展开；拓扑内部在 ±180 条带里工作，±180 两侧是不同的点。
- 布尔运算（`geo` 库）会把坐标舍入到约 1e-8°：`overlay::on_seam`、`at_pole` 把它们收回到日界线与极点上，`repair` 再吸附回精确顶点。
- 平面贝塞尔曲线在球面旋转下不是不变的：旋转曲线的控制点后必须重新细分，不能直接旋转细分出的点。
- JSON 往返可能改变浮点数最后一位；比较时用容差（工程文件用 MessagePack，精确）。
- **`HashMap`/`HashSet` 的遍历顺序每次运行都不同**。会影响输出的地方（导出、溶解边界的起点）必须先排序；`Document::dissolve_faces` 曾因此让同一个世界导出的 SVG 每次不同（M7 第五步已修）。世界生成的轮廓追踪、自动划分的追踪都用 `BTreeMap`。
- **布尔运算会把坐标舍入约 1e-8°**：叠加运算把输出吸回被切的面原来的顶点和所画多边形的顶点（`RepairOptions.prefer`、`overlay::exact_corners`，极点与日界线附近除外）。新的重建路径也要传入这些点，否则边界每画一次就漂移一点，之后沿它画的多边形会留下细缝。
- **面的 `rev` 是进程内唯一的几何版本号**（面积缓存的键），不是内容：同一个世界在同一进程里生成两次，`rev` 必然不同；读文件时也会重新编号。比较两个文档前先把 `rev` 清零（`map_io::project::without_revs`、`map_core/tests/worldgen.rs`）。

**测试与验证**

- 不写假测试结果；测不到的地方明确写"未验证"。
- 手动界面验证时用 `ATLAS_PREFS` 指向临时文件，测试窗口不要置顶，不要盖住使用者的其他窗口。
- 改了界面后，先 `build --release -p map_app` 再启动；`atlas.exe` 在运行时无法链接。
- 测试并行运行，界面语言是全局状态（`i18n::set`）：测试里不要读已经翻译的文字（用 `source_label`、`source_help`、`source_name` 等原文），否则会与切换语言的测试互相干扰——本机碰不到、GitHub 上碰到过。
- 测试程序所在的目录随 cargo 版本变化（较新的 cargo 放在 `target\release\build\<crate>\<hash>\out`）：按程序位置找文件时要一直向上找，不要假定层数。

## 7. 质量门槛与工作方式

- 每一步：功能 + 自动测试（核心逻辑必须有）+ 界面实测（能测的都测）+ `tools\check.cmd` 全绿 + 文档（`ARCHITECTURE.md` 一节、`ROADMAP.md` 进度、必要时 `DRAWING.md`/`API.md`）+ 本交接报告 → 一个提交。
- 提交信息英文，说明做了什么、为什么；结尾带协作者署名行。
- 拓扑、叠加、年份相关的改动之后跑一次深度压力测试：`ATLAS_SOAK_SEEDS=64 ATLAS_SOAK_STEPS=1500`（约 5–7 分钟），失败时会把出问题前的世界存到临时目录并给出文件名，可用 `ATLAS_SOAK_ONLY` 复现。

## 10. 最近一步：v0.1.0-alpha——导出国名修正、随附字体、公开发布（2026-11-17）

- 环形陆地（极点处另有国家或湖）在 0° 经线与日界线处各有一条同国的内部线；导入时洞包围极点的多边形不支持；穿过极点的边界画不出来。
- 国家、地块、城市仍是各自单选，没有并入统一选择；参考图、分区层没有并入图层栈。
- clippy 约 60 条旧警告，都在 M9 第四步之前的代码里，多为新版 clippy 的规则（`is_multiple_of`、`type_complexity`、`map_or` 等）；只是警告，`check.cmd` 不因此失败。新代码保持没有警告。
- 自动划分：一次一个方案；网格痕迹；大岛与细长半岛的面积均衡较差；不能划分无主陆地；省没有自动名称；在有极地大陆、跨日界线国家的复杂世界里仍有相当一部分尝试被拒绝（多为叠加运算在极点与日界线附近重建失败；文档不变）。
- 道路：不考虑已有道路、出城同向的路会部分重叠、不生成航线。
- 区域只能点在边线上选中（点在内部会平移地图）。
- 样式只覆盖线路、斜线区域、地图文字、符号的外观；河流沿用底图的河流样式；国家标注、城市、边界线没有命名样式。色板只是调色板，改色板里的颜色不会改变用过它的样式（不是"全局色"）。
- 符号样式只含大小与颜色，不含种类。
- 字体不嵌入工程；城市名、图例、标题仍用默认字体（随附的 Noto Sans SC，只有常规字重）；没有粗体字形的字体显示为常规字形。
- 国家名称：弯曲或铺开的名称在 SVG 中逐字写出（搜不到整个名称）；导出时国名尽量避开城市的点（避不开时压在点上）；拥挤的导出中河流与线路名、城市名可能被省去；拖动自动名称会变成直的手动名称；名称在球面边缘附近（压缩到 55% 以下）不画。
