# Atlas Forge 工程审查与维护计划

审查基线为 2026-11-21 的 Map Project 工作树及其版本锁，提交基点为 `5927dab`。检查覆盖八个 Rust 包及其测试、Windows 打包和持续集成入口。使用工作区全目标 Clippy 检查、已有回归测试、热点路径跟踪和固定输入的对照测试。工作树包含过去几轮尚待提交的功能，统计以本次实际构建为准。

## 本轮采用的改动

| 位置 | 审查发现 | 改动与证据 |
|---|---|---|
| `map_app` 标签布局 | 已占位的文字、城市和标志会被后续标签逐个扫描，密集时开销随两边数量增长 | 小集合沿用顺序查询，密集集合按屏幕网格查候选，再做原本的矩形相交判断。4,992 个矩形与 4,992 次查询的 Release 对照为 11.79 ms 对 0.69 ms，后者含 0.39 ms 建索引。对照保持相同结果，包括贴边和宽条区域。数值代表碰撞查询，界面的总帧时另行衡量。 |
| `map_app` 要素与图层 | 同一面板分别构建要素表与图层计数，重复排序、复制文本和计算地理中心 | 两处共享同一份要素清单。版本源限于四张要素表。切换年份或修改与要素内容无关的状态时，继续复用该清单。 |
| `map_app` 输入与双视图 | 没有键盘事件时也构建已翻译的快捷键列表，多处分别计算视图槽 | 按键事件到来时才查快捷键，二维和球体的槽位由视图类型统一提供。 |
| `map_core` 历史 | 删除最老快照需要搬移撤销表其余条目，旧的符号像素未进入保留内存估算 | 双端队列负责历史淘汰。仅在符号变更涉及不同图案时统计历史保留的图案数据，同一份图案在一次变更中计一次。 |
| `map_io` 工程与图形 | 工程写出为每个格式条件反复遍历画板，导出场景有两套空构造 | 每张画板一次参与本次格式决策，共用空场景构造。像素标志沿用相同图层与标签逻辑。回读时共享完全相同的像素数据，PNG 渲染复用像素纹理。 |
| `map_perf` 长录制 | HTML 图表在读完原始文件之后才抽样，图表数据读取阶段随帧数持续累积 | 每条曲线最多暂存约 14,000 个图点，读入时分桶保留极值。帧数和统计分位数仍以原始采样计算。18 万帧的合成录制中，峰值工作集从 33.5 MiB 降到 15.1 MiB，单次生成耗时分别为 2.02 秒和 2.17 秒。两份报告的帧数、分位数与 240 ms 峰值一致。 |

## 八个包的边界与风险

| 包 | 本次检查对象 | 下一阶段的工程问题 |
|---|---|---|
| `map_core` | 共享边拓扑、时间归属、变更集、撤销、绘制要素与世界册 | 历史内存预算对本文档、子画板、嵌套附件和共享数据的近似口径仍有差别。由各领域提供保留字节估算，保持现有原子编辑和旧档兼容测试。 |
| `map_io` | 格式选择、MessagePack 回读、独立画板、PNG、SVG、PDF、导出与原子写入 | 当前工程是整体序列化。先记录真实项目的编码时间、峰值内存和重复素材占比，再决定分块容器或增量提交。增加各格式的相同画板导出样本。 |
| `map_render` | 地形填充、共享边分块、GPU 缓冲代数、球面移动时的栅格缓存 | 多视图仍会收集可绘制块，设备提交与等待和 CPU 几何更新应分别计时。保留增量和全量的图形等价测试，以用户日志选择重做前端批处理的时机。 |
| `map_app` | 动作表、两套工作区入口、编辑事务、标注、画布输入、自动保存和关闭 | `App` 同时拥有文档和大量交互状态。先抽离要素清单、像素画笔这类有清晰生命周期的模块，下一轮给预览与编辑工具统一处理画板切换、取消和撤销。 |
| `map_api` | 本地会话、脚本、插件参数、草稿与批处理回滚边界 | 扩展自动化操作时统一能力登记与事务规则。对像素标志开放读写前，先规定载荷上限、显式提交和预览格式。 |
| `map_ai` | 不同服务商请求和返回、认证字段、草稿工具白名单 | 用固定服务商请求样本验证 JSON 映射。应把服务商差异留在适配层，继续通过同一个草稿接口验证编辑与提交权限。 |
| `map_perf` | 原始采样、后台写入、退出、人工标记和图表解析 | 图表内存已受限，长录制中精确分位数样本与事件回查仍增长。先增加长录制的 RSS 基线，再决定按时间分区或可选近似分位数。 |
| `map_bench` | 固定种子合成地图、历史与创作基准入口 | 将编辑会话、标注压力、录制与关闭拆成固定场景。采用独立试次和分位数，同代码及同机器间对照。 |

## 后续顺序与验收

1. **先守住文件和交互契约。** 在现有 Windows CI 中继续跑旧版地图、独立画板和批处理回滚。补同一组 PNG、SVG、PDF 的导出对照和含像素素材的剪贴板往返。每次格式变动验证根地图、活动子画板及只存在于非活动画板的功能数据。
2. **逐步收敛编辑状态。** 从地图对象的拾取、选中、拖动及撤销入手，把共同入口放在可独立测试的模块，并在每次替换时跑二维与球体的实际编辑。兼容旧的工具操作和输出格式。
3. **用采样决定规模优化。** 同样的真实项目记录空闲、二维拖动、球体转动、图层切换、导出、保存和退出，附版本、地图规模和图形后端。比较中位数、P95 和可稳定复现的卡顿。大批重复标志使读写成为瓶颈时，再为像素图与附件引入有内容标识的素材表。
4. **最后扩大平台覆盖。** 在 Windows 交付工具稳定后增加 Linux 和 macOS 编译与核心测试。图形驱动、文件对话框、字体和桌面输入各用实际运行验证。
