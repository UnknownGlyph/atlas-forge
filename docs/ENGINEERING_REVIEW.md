## 2026-11-27 · 像素标志的剪贴板往返

按“后续顺序与验收”第 1 项补上含像素素材的剪贴板往返。剪贴板文字（`map_io::clip`）带着每个标志的完整图案，图案能原样往返；但粘贴出的每个标志都各持一份图案，即使地图里已有相同的图案，或同一次粘贴中有几个标志用同一图案。重新打开的工程会共享相同的图案，粘贴却不会，于是重复的标志在内存、应用的纹理缓存和 PNG 渲染缓存（都按图案的地址）里各占一份。

`Document::paste_features` 现在让粘贴出的图案改用文档中已有的相同图案，同一次粘贴中相同的图案也只留一份，与读入工程的做法一致。撤销历史只对被替换的图案计数，粘贴本身不增加计数。测试 `map_io/tests/pixel_art.rs` 的 `pixel_marks_survive_the_clipboard_and_share_their_art` 经剪贴板文字把两种图案的三个标志粘贴到另一张地图（图案相同、重复者共享）、再粘贴一次（共享该地图已有的图案）、粘贴回原地图（共享原来的图案），并导出。改动前共享一项失败，改动后通过。

剪贴板文字仍按标志逐个写出图案（128×128 的图案逐像素写出，约 16 万到 26 万个字符，视颜色而定）；工程存盘同样按标志逐个写出图案（见第 3 项的素材表）。若要缩小剪贴板文字，需要新的剪贴板格式版本，并保持旧版文字可读。

## 2026-11-25 · 五项外部审查意见的核实

以发布后提交 `2c376d7` 为核对基线。

1. **App 的长期风险有实际例证。** 原 `reset_board_view` 清理了选中对象，但没有清除河流顶点拖动、部分草稿、测量与像素编辑目标。两个独立画板允许分配相同的对象 ID。本次提取 13 个工具手势字段，并在切工具、退出草稿、切画板和历史跳转处处理失效。窗口和渲染调度继续由 `App` 负责。拆分依据是状态何时失效。
2. **翻译资源受污染，导出损坏的推论未成立。** 九个原始 JSON 均未发现重复键或 Unicode casefold 后冲突的键。运行时按大小写精确查找。九个目录都误收了地图集的整段模板，但实际导出入口 `layout_ui → map_io::atlas::export_atlas → index_html` 独立渲染。已将模板移入 `atlas_index.html.in`，在提取和生成阶段拦截标记，并从每个目录移除模板及 291 个仅用于生成名字的词片。修订了“面不存在”和“（自身外观）”等实际界面误译。CI 校验 JSON 对象、键唯一、非空译文、格式字段的名称、次数和精度，以及混入的标记。语句的自然程度仍需人工校对。
3. **每次模型请求有子进程开销，SSE 受当前接口限制。** `Transport::post` 等待完整 JSON；绘图助手本来就能在工具步骤间显示日志。现有 Windows 路径保留系统 .NET 的代理与 TLS 行为，使用静态命令和 UTF-8 管道收发数据，减少中间文件和动态脚本拼接。curl 继续作为可选后端，使用独占临时请求文件。`ATLAS_AI_DEBUG` 只向标准错误输出 HTTP 状态和响应字节数。两类助手显示任务已用时间。本地回环测试覆盖两个后端的请求头、中文 JSON、HTTP 200 和 429。企业 EDR 拦截频率尚无现场数据，真实代理、分段事件、工具调用拼装与取消应作为将来迁移传输的验收条件。
4. **整体文件存在规模成本。** 对 100 张子画板各附 1 MiB 二进制资源，实测仅更改项目标题也会重写约 100 MiB。当前保留 MessagePack/LZ4 格式和原子替换。后续若要支持单板按需读取或小改动增量存盘，应以相同工程比较按内容寻址的附件和分块清单，验证旧档迁移及中断恢复后再变更格式。[存储基准](BENCHMARKS.md)
5. **功能跨度确实扩大，维护优先级需要基于覆盖情况。** 省级等分级标注已有缩放逻辑与测试，极区和日界线也有专门回归；极端拓扑、跨对象统一选择和道路规划仍有明确边界。新增模块已有专项测试，现补齐跨模块随机往返与架构索引。后续优先处理可复现的核心制图、数据持久性与误操作问题，再排新功能。[架构索引](ARCHITECTURE.md)

3. **用采样决定规模优化。** 同样的真实项目记录空闲、二维拖动、球体转动、图层切换、导出、保存和退出，附版本、地图规模和图形后端。比较中位数、P95 和可稳定复现的卡顿。大批重复标志使读写成为瓶颈时，再为像素图与附件引入有内容标识的素材表。
4. **最后扩大平台覆盖。** 在 Windows 交付工具稳定后增加 Linux 和 macOS 编译与核心测试。图形驱动、文件对话框、字体和桌面输入各用实际运行验证。
