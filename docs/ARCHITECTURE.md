# Atlas Forge — 架构设计与开发路线

> 本文件记录项目的可行性分析、技术选型、核心数据结构、早期必须确定的决策（ADR）、阶段路线与验收标准。
> 状态标记：✅ 已实现并有测试/可运行验证；🟡 部分实现；⬜ 计划中。

---

## 1. 可行性与关键技术难点

整体可行。功能面很宽，但真正决定成败、且后期难以修改的难点集中在少数几处：

| 难点 | 为什么难 | 本项目的处理方式 |
|---|---|---|
| **共享边界拓扑** | 相邻国家各存一份多边形 → 缝隙/重叠/编辑不同步；合并、分裂、割让需要可靠的几何运算 | 采用**平面拓扑（节点-弧段-面）**：边界弧只存一次，左右面引用；国家只是“面的归属”，合并/割让=改归属，不改几何 |
| **经度接缝与极地** | 跨 180° 的多边形在平面上被撕开；包含极点的多边形在经纬度平面不闭合 | 明确定义几何语义（ADR-2）：边取经度差 <180° 的方向；三角网在 CPU 上沿 ±180° 精确切割；包含极点的环用 lat=±90 伪边闭合 |
| **2D/3D 共享数据** | 两套几何会不同步 | 同一份经纬度三角网，投影在顶点着色器中完成：2D 各投影与 3D 球面只是不同的 shader 变换 |
| **样式与几何解耦** | 每次改颜色/专题图都重建网格会很慢 | 顶点只存 `(lon, lat, face_slot)`；颜色在单独的 storage buffer 中，换专题图只上传每面一个颜色 |
| **撤销/重做的正确性** | 拓扑操作牵涉多个对象，逆操作容易写错 | 文档使用持久化（结构共享）数据结构，撤销栈保存 O(1) 快照，无需手写逆操作 |
| **增量更新** | 大地图全量重建会卡顿 | 每个面有全局唯一的几何版本号 `rev`，网格缓存以 `(face, rev)` 为键，只重建变化的面 |
| **精度** | GPU 只有 f32 | 数据层 f64；GPU f32 经纬度 ≈ 1 m 精度，对创作地图足够；超大比例尺时改为相对视点中心坐标（已列入路线） |
| **文字标注** | CJK 字体、避让、2D/3D 一致 | 标注锚点在数据层计算（面积最大部分的内部点），视图层投影后贪心避让 |

## 2. 技术栈比较与选择

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| C++ / Qt 6 + OpenGL/RHI | 成熟的桌面控件；GIS 生态（GEOS、PROJ、GDAL）原生 | 本机未装 Qt；构建与依赖管理成本高；内存安全靠纪律；Qt 商业许可问题 | 可行但工程成本高 |
| **Rust + wgpu + egui (eframe)** | 单一工具链 `cargo` 即可构建；wgpu 映射到 DX12/Vulkan/Metal；内存安全；serde 生态便于文件格式；易写基准与测试 | 桌面控件不如 Qt 丰富（立即模式 UI）；GIS 库生态较 C++ 少 | **选定** |
| C# + Avalonia/Silk.NET | 开发快 | GC 停顿、GPU 绘制需要自写一层；高性能几何生态弱 | 不选 |
| Electron / WebView | — | 需求明确排除 | 不选 |

选择 Rust 的决定性理由：本项目最难的部分是**数据结构与算法的正确性**和**GPU 渲染**，而不是表单控件。Rust 在这两点上最有利；egui 的立即模式 UI 足以承担工具面板、属性表、图例编辑。若将来需要更复杂的停靠/表格控件，UI 层可替换（UI 只依赖 `map_core` 的公开 API）。

开发环境：Windows 11、MSVC 14.51 + Windows SDK 10.0.26100、Rust 1.99.1（通过 rustup 安装）。

## 3. 模块架构

```
crates/
  map_core    纯数据与算法，无 GPU/UI 依赖
    geom        经纬度、展开(unwrap)、平面算法、球面面积
    topo        节点/弧段/面 拓扑与编辑操作（加岛、切分、移点、插点…）
    doc         文档：拓扑 + 实体(国家/城市) + 字段定义 + 属性(含时间序列) + 归属 + 样式
    expr        派生指标表达式（如 pop / area_km2）
    theme       政治图 / 分级设色（等距、分位、手动阈值、渐变、缺失值）
    projection  投影（CPU 版本，与 WGSL 版本对齐）
    history     基于快照的撤销/重做
  map_io      工程文件(.atlas) 读写、GeoJSON、CSV、SVG、PNG 导出
  map_render  tess: CPU 三角化/切割/细分（纯函数，可测试）
              gpu : wgpu 管线（2D 投影视图、3D 球体），面填充 + 屏幕空间线宽边界
  map_app     eframe 桌面程序：工具、面板、视图、文件对话框
  map_bench   性能基准（合成大地图）
```

依赖方向严格单向：`map_app → map_render, map_io → map_core`。`map_core` 不依赖任何渲染、UI、文件格式。

## 4. 核心数据模型

### 4.1 几何与拓扑（ADR-1：平面拓扑）

```
Node  { id, pos: LonLat }                         // 弧段端点（交汇点）
Arc   { id, start, end, pts: Vec<LonLat>,          // 折线（不含端点）
        left: FaceId, right: FaceId }             // 沿弧方向的左/右面
Face  { id, kind: Land|Water, outer: Ring, holes: Vec<Ring>, rev }
Ring  = Vec<ArcRef { arc, rev: bool }>
```

- 不变量：面在其每条环的左侧（外环逆时针、洞顺时针）；正向引用的弧 `left == face`，反向引用 `right == face`。`Topology::validate()` 校验全部不变量，测试中每次编辑后都会调用。
- `FaceId(0)`（`topo::BACKGROUND`）是拓扑上的**背景面**：覆盖其他面之外的全部区域，没有外环，顶层环作为它的洞。这只是拓扑职责；它是海还是陆只由它的 `kind` 决定，和其他面一样（M2 完成，见下）。
- **国家不是几何**：国家/地区是 `Entity`，通过 `owner: FaceId → EntityId` 拥有面。
  - 合并国家 = 改归属；割让领土 = 改归属；飞地/多块领土天然支持；
  - 国界 = 两侧面归属不同的弧；海岸线 = 陆/水之间的弧；省界 = 同一归属内部的弧。三者从同一组弧派生，不可能出现缝隙或重叠。
- 编辑操作（均保持拓扑有效，失败时返回错误、文档不变）：
  - `add_ring_face`：在已有面内部画闭合环 → 新的陆地（岛）或水体（湖）；被包围的已有岛自动成为新面的洞；
  - `split_face`：从边界到边界画切割线 → 一个面变两个（绘制国界/行政区的主要方式）；
  - `move_vertex` / `insert_vertex` / `delete_vertex`：共享边界上的点只有一份，相邻两侧同时更新；校验不产生自交；
  - `merge_faces`：删除两个面之间的共享弧，合并为一个面。

### 4.2 坐标与投影（ADR-2：几何语义）

- 存储：经纬度 `f64`（度）。经度规范化到 `[-180, 180)`，纬度截断到 `[-90, 90]`；经度 +180 存为 −180。
- **边的定义**：相邻两点之间的边取经度差绝对值 < 180° 的方向，并在经纬度平面上为直线（线性插值）。
  经度差恰好为 180° 时取向东方向（`lon_delta` 返回 +180）。这与 GeoJSON 对不跨反经线线段的线性插值定义一致，使平面算法（耳切三角化、相交、点在多边形内）可直接使用。
  注意：经纬度平面上的直线**不是**恒向线（恒向线是墨卡托投影上的直线），也不是大圆。与大圆的偏差随边长和纬度增大；
  二维绘制工具会沿屏幕直线自动加密取点（每 24 像素一个点），因此用户绘制的边都很短。量化的误差上限（以米或屏幕像素计）尚未给出，列入 M2。
- **环所表示的区域**：环左侧的区域，在展开后的经纬度柱面上取平面内部；外环一律规范为逆时针、洞为顺时针。经度绕行 ±360° 的环包含一个极点（向东绕行包含北极）。
  因此一个面在柱面上的平面内部是唯一的，不存在“取较小的那一半球”这种歧义；代价是不能表示同时包含两个极点的面（P3 再处理）。
- 需要大圆语义的对象（航线等）将来作为专门的线要素处理，不改变面的边语义。
- 面积：对“经纬度直线边”在**球面**上的精确积分 `A = R² ∮ -sin φ dλ`（格林公式），星球半径可配置。
  测试中与解析解的**相对**误差 < 1e-12（经纬度矩形、半球）。这是对本项目边语义的球面精确值，不等于真实地球椭球面积；椭球面积计划在需要时作为可选口径加入。
- 包含极点的环：展开后经度绕行 ±360°，用 lat=±90 伪边闭合后即为普通平面多边形。渲染、导入（如南极洲）、移动其顶点都已支持；绘制工具暂不允许画出此类环。
- 投影是视图变换，不修改数据：等距圆柱、墨卡托、米勒、Equal Earth；中央经线可调（改变接缝位置时重新切割网格）。
- 二维地图上点击的位置经反投影成为经纬度；三维球面拾取通过射线-球求交得到经纬度——之后的选择、编辑走同一套逻辑。

### 4.3 属性与统计（ADR-3：可扩展字段 + 时间维）

```
FieldDef { id, key, name, kind: Number|Text|Bool|Category, unit, derived: Option<Expr> }
Entity   { id, kind: Country|Region|City, code(稳定外部ID), name, short, color, parent, capital }
values   : (EntityId, FieldId) → Series { base: Option<Value>, by_year: BTreeMap<i32, Value> }
```

- 用户可自建任意字段；内置字段只有“面积”（由几何计算）。
- 时间序列从第一天就进入数据结构：取值规则为“≤ 当前年份的最近值，否则基础值”。时间轴 UI 与版图历史（归属随时间变化）在 P3 实现，但不需要改文件格式。
- CSV 导入以 `code`（用户可见的稳定 ID）关联实体；可选 `year` 列写入时间序列。
- 派生指标：`expr` 模块支持四则运算、括号、字段引用，例如 `gdp / population`、`population / area_km2`。

### 4.4 撤销/重做（ADR-4：持久化数据结构快照）

`Document` 的各个表使用 `imbl::OrdMap`（结构共享的持久化 B 树）。克隆是 O(1)，修改只复制路径上的节点。撤销栈保存修改前的文档。
优点：任何编辑操作都自动可撤销，不需要为每个拓扑操作写逆操作（这是此类软件最常见的 bug 来源）；也天然支持“编辑失败时回滚”。代价：读写常数比 `HashMap` 大约 2–4 倍——基准测试证明可接受。

### 4.5 渲染（ADR-5：投影在 GPU 上完成）

- 每个面 → 展开环 → 耳切三角化 → 细分到最长边 ≤ 2°（用于球面贴合与投影曲率）→ 沿 ±180°（相对中央经线）精确切割 → 顶点 `(lon, lat, face_slot)`。
- 网格与投影无关：切换投影/切换 2D↔3D 不重建网格；颜色在 per-face storage buffer 中。
- 边界线：每条线段作为一个实例，在顶点着色器中投影后按屏幕像素宽度扩成四边形（任意缩放下线宽恒定，矢量清晰）。
- 3D 球体：海洋球 + 陆面网格（同一个网格）；片元着色器做地平线剔除，无需深度缓冲。

### 4.6 文件格式（ADR-6）

`.atlas` = 魔数 `ATLASMAP` + 格式版本(u32) + LZ4 压缩的 MessagePack(`Document`)。
- 保存时先写临时文件再原子替换，避免崩溃导致工程损坏；
- 版本号 + serde 默认值用于向后兼容迁移；
- 交换格式：GeoJSON（按面或按国家融合导出、导入）、CSV（属性）、SVG（真正的矢量路径）、PNG（独立 CPU 光栅器渲染，任意分辨率，不是截屏）。
- 后续可能迁移到 SQLite 容器以支持增量保存（P4 评估），当前格式的版本号机制保证可迁移。

## 5. 必须最早处理的决策（否则会重写）

1. 平面拓扑 + 国家=面的归属（ADR-1）。若一开始用“每个国家一组多边形”，后期加入共享边界与合并/分裂几乎需要重写全部编辑器与文件格式。
2. 统一经纬度坐标与边语义（ADR-2）。2D/3D/导出/拾取全部依赖它。
3. 稳定 ID（不是数组下标）：CSV 关联、撤销、文件兼容、插件都依赖。
4. 几何与样式分离的渲染数据（ADR-5）。
5. 属性带时间维（ADR-3）。
6. 撤销机制（ADR-4）。
7. 文件格式版本号（ADR-6）。

## 6. 阶段路线与验收标准

### P0 — 结构正确的最小核心（当前阶段）
目标工作流：**新建地图 → 绘制陆地 → 切分国家 → 编辑边界 → 保存 → 重新打开 → 三维球体 → 修改统计数据 → 专题图 → 导出**。

验收标准（可验证）与当前状态（2026-10-28）：
- [x] `cargo test --workspace` 27 项全部通过：拓扑不变量在每个编辑操作后成立；跨 180° 的岛屿正确切分、三角化与 GeoJSON 分割；面积公式与解析值一致（1e-12）；保存→读取后文档逐字段相等；GeoJSON/CSV 往返；撤销/失败回滚。
- [x] `crates/map_io/tests/workflow.rs`：无界面跑通完整工作流（绘制 → 切分 → 改边界（总面积守恒）→ 保存 → 读取 → 统计/派生指标 → 分级设色 → 导出 PNG/SVG/GeoJSON/CSV）。
- [x] `map_bench` 输出基准表（见 BENCHMARKS.md）。
- [x] 桌面程序可启动；二维（Equal Earth）与三维球体同时显示示例世界；在界面中绘制陆地后，二维与球体同一帧更新（已人工截图确认）。
- [x] 界面人工验证（release 构建，2026-10-28）：绘制陆地（单击闭合与回车闭合）→ 切分 → 领土画笔（新建两个国家并分配）→ 拖动共享边界顶点（两侧与球体同步更新）→ Ctrl+Z 撤销 → 导出 PNG（3000×1600，65 ms）。
  验证中发现并修复的问题：① 二维视图中跨越 >180° 经度的长笔画会被解释为反方向（现按屏幕直线加密采样，含回车闭合的闭合边）；② 快速拖动顶点时按拖动识别后的位置取点导致抓不到顶点（改为按下位置）；③ 窗口尺寸变化后二维地图不重新适配；④ PNG 标注描边呈斑点状。
- [x] 第二轮界面验证（2026-10-28）：墨卡托/米勒/等距圆柱三种投影显示；样式修改撤销（滑杆拖动合并为一步）；数据表编辑（派生字段同步更新）；合并相邻面；右键删除顶点；导出 SVG、GeoJSON（国家）、CSV 并检查文件内容。
- [x] 随机操作序列测试（`crates/map_core/tests/random_ops.rs`）：岛/湖、切分、移点、插点、删点、合并、撤销/重做随机组合，每步检查全部不变量，并抽样验证“每个点恰好属于一个面”（无重叠、无缝隙）。默认 40×120 步随测试运行；15 万步的加压运行（`ATLAS_FUZZ_SEEDS=500 ATLAS_FUZZ_STEPS=300`）发现一个真实缺陷：顶点跳过整个小面时环被翻转但仍是简单多边形，现已修复并加回归测试。
- [ ] 尚未验证：真实断电。

已知限制（P0）：新画的多边形不能与已有边界相交或接触（不做自动并集/裁剪）；GeoJSON 导入不识别相邻多边形的共享边；包围极点的环只能显示、不能用工具绘制。

### 外部评审后的路线调整（2026-10-28）

评审结论：保留现有核心架构（共享边拓扑、国家与几何分离、二维/三维共享数据、持久化快照撤销），不更换 UI 框架，暂不迁移 SQLite；
把真实数据导入、编辑可靠性和历史版图语义提到专题图样式之前。原 P1–P5 改为三个里程碑，其余功能排在其后。

**M1 编辑与保存可靠**（已完成，2026-10-28）

- [x] 样式、专题图、世界参数、国家颜色/备注的修改进入撤销栈，并参与“未保存”判断（连续拖动合并为一步）。
- [x] 随机操作序列测试 + 修复其发现的缺陷。
- [x] 自动保存与崩溃恢复：有未保存修改时每 60 秒在后台线程写快照（`%LOCALAPPDATA%\AtlasForge

- [x] 变更集（`map_core::change::ChangeSet`）：任意两个文档状态之间改动了哪些节点、边、面、归属、实体、字段、数值。

  - 测试：变化点区间语义与去冗余；有历史时拒绝“所有年份”编辑且文档不变；切分共享历史、历史不同的面不能合并；合并/删除国家改写各年份；**60 步随机编辑（领土画笔、夺取、扩张，局部与整体两种路径）在随机年份进行，每一步之后所有更早年份的各国面积与编辑前完全相同**（故意去掉历史继承后此测试会失败）；存盘往返与旧文件读取。界面验证：示例世界中 1900 年起把一国划给另一国，1899 年显示原状，“下一变化”跳回 1900。
- [x] 第二步：上级关系随时间变化（ADR-7 的 `(实体, [开始, 结束)) → 上级`）。
  - 与归属同一模式：`parent_base`（沿用文件中的 `parent` 字段）+ `parent_changes`（年份 → 从该年起的上级，None = 顶层）；`Entity::parent` 是所选年份的派生值，`top_ancestor`、国界/内部边界分类、专题着色都随年份变化。面只记录最细一级归属（如省），省从某年起改属另一国时只需改上级。
  - 写入只经过 `record_parent`：年份规则同归属；在该年及之后所有变化年份检查环路（不能让实体成为自己的上级），失败时文档不变；合并/删除实体改写所有年份的上级引用；城市的上级（所在国家）也走同一接口。
  - 界面：国家面板新增“上级”选择（选了年份时为“从该年起改变上级”），并显示上级关系历史；时间轴的变化年份包含上级变化。
  - 测试：省份从某年起改属另一国，之前年份顶层国家不变；有历史时拒绝“所有年份”编辑；之后年份产生环路时拒绝（包括在较早年份设置、但与之后的变化构成环路的情况）；合并/删除改写上级；**80 步随机上级修改（省改属、国家嵌套，含被拒绝的环路）后，所有更早年份的“面 → 顶层国家”映射与修改前完全相同**（故意让带年份的修改覆盖所有年份时此测试会失败）；旧文件读取。界面验证：沙洲联盟从 1900 年起隶属高地邦，1900 年两国着色相同、共同边界变为内部边界，1899 年恢复原状。
- [x] 第三步：逐年批量导出（`map_io::batch`）。
  - 导出窗口勾选“逐年导出”：年份取“变化年份（含第一次变化前一年的最初状态）”或“区间 + 步长”；输出到指定文件夹（可输入或浏览，下次沿用），文件名 `工程名_年份.扩展名`（年份补零便于排序，公元前为 `-0200`）。支持 PNG、SVG、GeoJSON（国家/地块）、CSV，每个文件都是该年的归属、上级与数据；PNG/SVG 标题中的 `{year}` 替换为年份（不含时追加年份，留空则只写年份）。
  - 后台线程按 CPU 核数并行渲染，导出窗口显示进度条并可取消；完成后状态栏报告文件数和耗时。单张导出也改用同一个 `write_one`。
  - 测试：年份列表与命名规则；三年 GeoJSON 中各年出现的国家正确；SVG 标题含年份；导出不改动文档的年份；取消时不写文件。界面验证：示例世界 1900 年起改变归属后逐年导出 PNG，得到 1899、1900 两张 3000×1600 图，标题、着色和图例分别对应各自年份（约 0.1 s）。
- [x] 第四步：多个分区层（ADR-7 的“分区层”，先做独占层）。
  - 每一层是同一组地块的一种独占划分（政治归属、实际控制、文化区……），有自己的单位（实体带 `layer`）和自己的时间线。`LayerId(0)` 是政治层；其他层的归属存放在 `Document::layers`，**当前层**的归属就是 `owner_base/owner_changes`（切换层时交换存放），所以渲染、专题、统计、标注、导出、时间轴和所有编辑工具无需改动即作用于当前层。旧文件即只有政治层。
  - 几何操作同步所有层：切分时每一层的两半共享历史；合并要求所有层（和所有年份）归属相同；背景改为海洋时清除所有层的背景归属；“绘制陆地”产生的新面在每一层都继承来源面的历史，只在当前层记录新归属。合并、嵌套单位只能在同一层内；删除层会删除它的单位（政治层不能删除）。
  - 界面：国家面板顶部的“分区层”选择、新建、重命名、删除；单位列表、领土画笔、扩张/夺取只用当前层的单位；切换层不产生撤销步骤。
  - 测试：两层是同一组地块的独立视图，切换不丢数据；跨层合并/嵌套被拒绝；在文化层切分、合并（两层历史不同时拒绝）、绘制夺取后，政治层各国面积不变（故意不让非当前层继承来源历史时此测试失败）；各层时间线独立；存盘往返（以文化层为当前层保存）与删除层。界面验证：新建“分区层 1”，新建单位并涂三块地，切回政治层地图不变，再切回分区层涂色仍在。
- [x] 第八步：海岸线随时间变化。几何仍是所有年份共用的一套拓扑，变化的是每块地的海陆：`kind_base` + `kind_changes`（年份 → 从该年起为陆地/水域），拓扑中的 `kind` 是所选年份的派生值（未选年份为最新状态），所以某年的海岸线就是该年海陆之间的边，渲染、统计、导出无需改动。水域年份的地块没有归属（其他年份的归属保留）。
  - 编辑：选了年份时，在海中画的岛、在陆地中画的湖/海湾从该年起出现（之前与所在面相同：同样的海陆、各层同样的归属）；跨越海岸的“绘制陆地/变为水域”在选了年份时走显式整体重建，每个新面继承来源面（包括海洋背景）的海陆与归属历史，再在该年记录新的海陆与归属，不合并不同历史的水面；所选地块可“从该年起变为水域/陆地”。未选年份时修改所有年份（有历史的面拒绝）；切分复制海陆历史，合并要求海陆历史相同；背景的海陆仍在样式中固定设置。
  - 测试：1950 年画的岛 1949 年是海、1950 年陆地面积增加；1950 年画的湖 1940 年仍属该国、1960 年无归属；陆地→水域→陆地往返后归属恢复；切分共享、历史不同不能合并；1950 年跨海岸“夺取”与 1960 年开凿海湾后，1900、1955 年的陆地面积和各国面积不变，存盘往返（故意不继承海陆历史时此测试失败）。界面验证：1950 年在海中画岛，1949 年岛消失；东陵公国“从 1950 年起变为水域”，1950 年消失、1949 年仍为陆地且面积和归属不变。
  - 代价：选了年份的跨边界绘制总是整体重建（4000 国约 0.5 s），未选年份时仍走局部拼接。
- [x] 第七步：动画导出。逐年导出的“输出”可选每年一个文件、动画 GIF 或视频 MP4（PATH 中有 ffmpeg 时可选，否则灰显）；每年显示时长可设，最后一年停留两倍时间；帧按地图选项（尺寸、投影、标题模板 `{year}`、标注、图例）渲染，按 CPU 核数分批并行渲染、按年份顺序写入，有进度和取消，取消或出错时删除半成品。GIF 用 `image` 编码（每帧 256 色，循环播放）；MP4 把原始帧经管道交给 ffmpeg（H.264、yuv420p、尺寸补成偶数、30 fps、faststart），停留用重复帧实现。
  测试：GIF 帧数等于年份数、最后一帧停留两倍、尺寸正确、相邻年份画面不同；有 ffmpeg 时 MP4 生成；取消不留文件。界面验证：示例世界 1900 年起改变归属，导出 1280×720、每年 1 秒：MP4 为 3.0 s / 90 帧，GIF 为 2 帧 / 3.0 s，抽帧检查 1899、1900 两年画面与标题正确。
- [x] 第六步：比例层（ADR-7 中文化、宗教等“比例分布而不是单一归属”）。
  - 新建层时可选“独占层”或“比例层”。比例层中每块地存各单位的比例（万分点整数，总和不超过 100%，其余为未知/其他），同样有“起初 + 年份变化点”的时间线和相同的年份规则（未选年份时不能改有历史的地块）。
  - 显示与统计：地块颜色按比例混合各单位颜色（未分配部分用陆地色）；面积按比例计入各单位（60% × 地块面积）；派生的 `owner` 取比例最大的单位，因此标注、叠加线、导出和其他层的叠加照常工作；图例包含所有持有比例的单位；导出不按单位合并，而是逐块用混合色。
  - 编辑：比例层中领土画笔有“画笔比例”，涂抹时把画笔单位设为该比例、其他单位按比例缩小；右键清空；在其他层编辑几何（切分、合并、背景、绘制）时比例随之继承；在比例层“夺取”时新区域整块归该单位（100%）。
  - 测试：比例重新分配与取最大；面积按比例、颜色按比例混合、画笔 = 100%、清空；随年份变化且不影响更早年份、有历史时拒绝“所有年份”编辑；比例编辑不影响政治层，政治层绘制后各单位按比例的面积不变；切分复制比例、比例不同不能合并、存盘往返、删除单位时移除其比例。界面验证：新建比例层，单位 1 涂某地 100%，单位 2 以 40% 再涂，地块呈混合色，面板显示 60% / 40%，两单位面积相加等于地块面积。
- [x] 第五步：同时显示两层。当前层照常填色，另选一层以彩色边界线叠加（如政治填色 + 实际控制线）：两侧陆地在该层（所选年份、按其上级关系取顶层单位）不属于同一单位的边即为叠加线，海岸不重复画。选择、颜色、线宽存于样式（可撤销），屏幕与 PNG/SVG 导出（包括逐年导出）一致。渲染使用第 8 个线型槽，叠加线只在拓扑、各层归属、实体、年份、当前层或叠加设置变化时重算。
  测试：叠加线恰好是该层归属不同的陆地边；该层自己的时间线移动叠加线（1899 与 1900 不同）；当前层不会叠加自身；导出场景中出现叠加线、未选择时没有。界面验证：分区层 1 中把河谷国和高地邦涂为同一单位，切回政治层并叠加分区层 1，两国外缘出现红线而两国之间没有。

**之后**：面内索引网格 → 以共享边为单位的 LOD 与按屏幕误差细分 → 视口裁剪（按块跳过不可见部分）→ 相对视点中心坐标；
标注手动编辑（拖动、固定、按缩放级别显示）与成图版式；更多专题图方法；地形；glTF；插件系统。

### ADR-7：历史归属与几何变化（2026-10-28 产品方已确认核心规则）

评审指出：只给 `owner` 加年份不够——之后移动边界时，同一份几何会改写所有年份的地图。草案：
- 归属表改为 `(面, 层, [开始, 结束)) → 实体`；同一独占层内同一时刻每个面最多一个归属，允许“未归属/未知”。
- 层级关系同样带时间区间：`(实体, [开始, 结束)) → 上级实体`。严格嵌套时只记录最细一级归属，上级由层级关系推出；允许“已归属国家、尚未划分省县”。
- 分区层：政治归属、实际控制、行政区划、文化/宗教等，声明是否允许重叠（文化、宗教可能需要比例分布而不是单一归属）。
- **边界变化的表达**：“从某年起割让一块领土”= 先把面沿新界线细分（细分对所有年份生效，早期年份两侧归属相同，显示时隐藏内部边），再修改新面在该年之后的归属。
  因此拖动边界在交互上必须区分两种意图：“修正所有年份共用的几何错误”与“从某年起发生边界变化”（后者自动转为细分 + 归属变化）。
- 统计口径：面积等几何派生值按所选年份的归属计算；边界变化后人口等数据不默认按面积比例分摊。
- 海岸线、地貌变化需要几何本身的版本，暂不实现。

**已确认（2026-10-28）**：修改某一年之后的边界**不得改变更早年份的地图**。边界变化一律表达为“细分 + 从该年起改归属”；“修正所有年份共用的几何”作为单独、明确标示的操作提供。

**已确认（2026-10-29）：数据的年份语义**（产品方给出原则，实现细节由开发决定）
1. 无年份的基础值独立存在，不自动归属于任何年份；未选年份（普通地图）时直接使用基础值。
2. 每个字段有“年份继承”策略：严格年份（只用该年记录，否则未知）、最近历史值（不晚于该年的最近记录）、基础值回退（该年记录，否则基础值）、线性插值（仅数值，在前后两条记录之间插值，范围外未知）。未设置时按类型取默认：数值统计（人口、GDP 等）为严格年份；文本、分类、布尔等静态属性为基础值回退。国家名称、颜色、样式本身就是静态属性，不随年份变化。
3. 字段可设“基础值年份”（如“最新数据 = 2020 年”）：基础值只作为该年的一条记录参与（同年的真实记录优先），不会自动套用到最后一条记录之后的所有年份。
4. 每次取值都带来源：该年记录、基础值、沿用某年、两年间插值、计算值、未知；零是值，与未知区分。数据表、专题图标题（如“人口（1960 年，9 个插值）”）显示来源；选了年份时 CSV 与 GeoJSON 导出为每个字段附带 `<键>_source` 列/属性（CSV 再导入时忽略这些列）；未选年份时导出保持原样。
5. 编辑数据表时只修改所选年份自己的记录（未选年份时修改基础值），继承、插值得到的值只作为提示显示，不会被当作记录写回。

**已确认（2026-10-29）：统计的边界口径跟随数据所属年份**（`map_core::stats`）。
- 由面积计算的值（如密度 = 人口 / 面积）使用其输入数据所属年份的边界：查看 1950 年而人口沿用 1900 年记录时，除以 1900 年的面积，并标明“口径：1900 年边界”；该年自己的记录用该年边界；插值和无年份基础值用所选年份边界；设了“基础值年份”的基础值视为该年的数据；输入来自不同年份时用所选年份边界并标为“混合口径”。内置面积字段本身始终是所选年份的面积。
- 其他年份的面积在一次统计中只计算一次（`Stats` 上下文按年份缓存），数据表、专题图、CSV / GeoJSON 导出共用；专题图标题注明“n 个按数据所属年份的边界 / 混合口径”，导出的 `_source` 为 `derived:borders-1900`、`derived:mixed` 等，数据表中这类计算值带“*”，悬停显示口径。
- 测试：沿用 1900 年人口时按 1900 年两块领土的面积计算、1960 年记录时按 1960 年一块领土计算、插值用所选年份、两年输入为混合口径、基础值年份生效、图例标注。界面验证：示例世界人口改为“最近历史值”，1950 年数据表中人口密度带“*”，悬停显示“计算值，口径：1900 年边界”。
（原实现“不晚于该年的最近值，否则基础值”导致示例世界选 2000 年时显示 1900 年人口，已按上述规则替换：示例世界的人口基础值年份为 2020、策略为线性插值，1960 年显示 1900–2020 的插值并标明来源。）

## 7. 性能基准方法

`map_bench` 生成合成世界（N×M 网格切分的大陆，可达数万个面、数十万顶点），测量：
- 全量三角化时间与顶点数；单面增量重建时间；
- 保存/读取时间与文件大小；
- 点选（反投影 + 点在面内）延迟；
- 一次 `move_vertex` + 校验 + 撤销的延迟；
- 进程常驻内存（Windows 下通过 `GetProcessMemoryInfo`）。

结果记录在 `docs/BENCHMARKS.md`，每次性能相关修改后重跑并比较，不凭感觉宣称“已优化”。


## 9. 第二轮外部评审（2026-10-29）后的调整与 M4 计划

评审基于 `docs/M3_SUMMARY.md`。以下为采纳情况与排序（开发方主导，产品方要求优先增强绘制能力与体验）。

**已立即采纳并完成**
- **显式事件不再被静默删除**：原实现会在记录新变化点时压缩所有“与前一状态相同”的点；例如已有“1950 年起归乙”，再记录“1920 年起归乙”会删掉 1950 年这一点，之后再插入“1930 年起归丙”时，作者设置的“1950 年恢复乙”已经丢失。现在记录某年时只在“该点与紧前状态相同（无效操作）”时不保存该点，其余变化点都保留为作者设置的事件；只有合并/删除实体（身份改变）时才整体压缩。归属、上级、海陆、比例四类历史一致。回归测试即上述场景。
- **撤销保持当前浏览年份**：撤销/重做后回到原来正在看的年份，并在状态栏说明“该修改在 1900 年”；不再自动跳转。

### M4 第一步：绘制体验（2026-10-30）
- [x] 草稿模型：草稿只保存用户的点（单击、手绘、描线结果），沿屏幕直线的加密改在提交时进行，因此草稿点可以编辑：拖动草稿点移动、拖动线段中点手柄插入、右键删除；Backspace 撤回、Esc 取消。
- [x] 吸附与描线（`map_core::trace`）：绘制陆地/湖泊/切分时，点击靠近边界/海岸（8 像素）自动吸附到顶点或边；前后两个点都吸附在边界上时，沿已有边界（共享边的精确顶点）以最短路径连接，两端都在海岸上时只沿海岸走、不穿过内陆国界；悬停时以绿色预览描线路径；工具栏可关闭，Ctrl 临时关闭。Shift 将方向约束为 15° 的倍数。
- [x] 手绘：在地图上按住拖动即手绘，松开后按屏幕 1.5 像素做 Douglas–Peucker 化简；终点吸附到边界，回到起点附近自动闭合；切分线落在边界上即完成。
- [x] 预览：闭合草稿按结果着色（陆地色、画笔国家色、湖泊色）半透明填充，旁边显示约略面积、绘制意图（新增陆地 / 扩张 / 夺取 / 变为水域）以及“某年起”。
- [x] 后台执行：需要整体或局部重建的绘制在后台线程计算，地图上显示进度；期间若地图被修改则结果作废并恢复草稿；计算失败也恢复草稿以便修改后重新提交。
- 测试：描线（沿海岸而不穿过内陆国界、同一条边上的片段、不相连时返回空）、化简保留拐角、吸附后触及海岸的岛经重建得到有效拓扑。界面验证（示例世界）：吸附指示；两海岸点之间的绿色描线预览，提交后草稿沿海岸走；海中手绘直线化简为两点；拖动草稿点移动、拖动中点手柄插入（面积随之更新）；右键删除草稿点；回车提交后新陆地与高地邦、沙洲联盟共享海岸边界（经后台路径，5 ms）；切分工具手绘穿过新陆地，落在边界上自动完成。后台进度提示因计算太快（5 ms）未能目视确认。

### M4 第二步：线条风格、边界重塑、画出新国家（2026-10-30）
- [x] 线条风格（`map_core::shape`）：绘制陆地/湖泊/切分线/河流时可选“原样 / 平滑 / 自然（海岸状）”。平滑为 Chaikin 角切；自然为确定性的分形中点位移（同一线段每次结果相同，增删其他草稿点时已画好的部分不跳变），粗糙度可调，细节密度取当前缩放约 4 像素。沿边界描出（两端都吸附）的线段与吸附点保持不动，因此风格化后的形状仍然准确接上已有边界；结果若自交，粗糙度逐次减半，仍不行则保持原样。预览中深色轮廓即最终提交的形状。
- [x] 已有边界重塑：选中地块后可“平滑 / 自然化”它的全部边界（与邻国共享的边界一起改变，所有年份共用）。先按目标尺度化简再施加风格，因此已有密集顶点的海岸也能明显呈现风格；所有交汇节点保持不动；每条边经 `Topology::replace_edge_points` 校验（不相交、洞仍在面内、岛不互相包含），任何一条失败则整体撤回。
- [x] 绘制模式“画出新国家”：画完即新建国家（自动命名），区域内全归它，并设为当前画笔。
- 测试：自然风格确定、保持简单多边形、保留拐角、零粗糙度不改形状；固定线段与固定点不动；平滑保留开放线段端点并削去尖角；示例世界每个陆地面轮流平滑/自然化后拓扑有效、节点数不变、陆地总面积变化 < 5%。界面验证：自然风格的岛（预览与提交形状一致）；“画出新国家”跨越沙洲联盟海岸与新岛，得到新国家12（新增 3,507,636 km²，取自无主地 2,091,972、沙洲联盟 1,140,173，与其面积 6,739,781 km² 相符）；北原王国“平滑”“自然化”后海岸与国界明显变化。

### M4 第三步：重塑边界的预览确认与保持面积（2026-10-30）
用户指出的两个问题：已有边界的重塑会作用于所有历史年份，容易误改历史地图；平滑与自然化会改变实际国土面积。
- 边界几何仍然是所有年份共用的（拓扑只有一份；按年份分别保存几何会让共享边界在不同年份失配，代价远大于收益）。因此不让它“静默生效”：点击“平滑… / 自然化…”只计算候选结果，地图上以橙色画出新边界、灰色画出原边界，窗口列出当前年份各国面积变化（km² 与 %）、所有年份视图中单个国家的最大面积变化，以及“会同时改变 N 个年份视图”的提示；确认“应用”才写入（一步撤销），“取消”不留痕迹。期间若地图被其他操作修改，预览自动作废。
- 保持面积（默认开启，`shape::preserve_area`）：每条边风格化后沿法向修正，使新旧两条线之间的有向面积为零（开放边，两端节点不动、位移从两端渐入）或环面积不变（单边岛），因此边两侧的每个面面积都不变——无论哪一年谁拥有这些面，所有国家在所有年份的面积都保持。面积在等积坐标（经度 × sin 纬度）中计算，与地图报告的球面面积一致；若某条边无法在不自交的前提下保持面积（例如缩小视图时化简成直线），该边保持原样。绘制草稿的风格化同样默认保持所点形状的面积（河流除外）。
- 测试：带 1900 年领土变化的示例世界，每个陆地面轮流平滑/自然化，在细、粗两种细节尺度下，各国在 1899、1900 与无年份视图中的面积相对变化均 < 0.1%，而不保持面积时变化大 10 倍以上；开放折线与闭合方形的修正精确到 1e-6；直线无可修正点时返回 None。界面验证（示例世界，1900 年）：沙洲联盟“自然化…”预览，保持面积时最大变化 0.0022%（−181.9 km²），关闭后为 +7.57%；应用后面积 8,328,616 → 8,328,434 km² 与预览一致，状态栏“改变了 2 条边，面积保持”；撤销后恢复 8,328,616 km²。修正前曾在缩小视图下测得 0.8% 残差（化简成直线的边无法修正），已改为该边保持原样并加入粗尺度测试。

### M4 第四步：重画国界（2026-10-30）
与重塑边界（改几何、所有年份共用）互补的、按年份生效的边界修改方式：
- [x] 新工具“重画国界 G”（`map_core::redraw`）：从边界上一点出发画出新的走向，落回边界即完成。程序沿已有边界找出两端之间的原边界（与描线相同的最短边界路径），新线与原边界围成的区域整体移交给原边界对侧的国家；对侧是海则该区域变为水域，从海一侧向外画则新增陆地。它走绘制陆地的同一套叠加重建（`overlay::apply`，夺取/变为水域），因此是领土（或海陆）变化：选了年份时只从该年起生效，更早的地图与面积不变；无年份时改当前地图。
- [x] 判定与拒绝：沿原边界多处采样两侧，对侧必须始终是同一个国家或海（例如一端在国界、一端在海岸时拒绝）；新线与原边界交叉、起终点相同、对侧是无主地、两侧同属一国时给出明确提示，草稿保留以便修改。
- [x] 预览：画线过程中光标停在边界上时，以获得方的颜色填充将移交的区域，并标出约略面积、“从 A 移交给 B（某年起，更早的地图不变）”；落点即完成，后台计算，可撤销。
- 测试：两国方块中，向对方凸出的新国界在 1950 年把土地移交给本方（1899、1900 年两国面积不变；1950 年陆地总面积不变，一方增加量等于另一方减少量），反方向则移交给对方；海岸向外画新增陆地、向内画变为水域，拓扑有效；跨国界与海岸、交叉、同一点均被拒绝。界面验证（示例世界，1900 年）：在北原王国与沙洲联盟之间向沙洲联盟一侧画出新国界，预览显示“约 1,498,653 km² · 从沙洲联盟移交给北原王国（1900 年起，更早的地图不变）”，提交后状态栏“从沙洲联盟取得 1,503,622 km²；7 ms”，北原王国 11,416,413 → 12,920,035 km²、沙洲联盟 8,328,616 → 6,824,994 km²（差额一致）；切到 1899 年两国边界与面积均为原样。预览面积按草稿直线计算，提交时沿屏幕直线加密，两者相差约 0.3%。

### M4 第五步：选定年份时编辑顶点 = 领土变化（2026-10-30）
编辑顶点原本直接修改所有年份共用的几何，同样有误改历史地图的问题。
- [x] 时间轴选定年份且“选定年份时作为领土变化”开启（默认）时：拖动国界上的点（已有顶点，或边上任意一点）在拖动过程中不修改地图，只按“上一个点 → 新位置 → 下一个点”生成重画国界的计划（`redraw::drag_line` + `redraw::plan`），预览将移交的区域和“从 A 移交给 B（某年起）”；松开后作为从该年起的领土变化应用（一步撤销）。右键删除顶点同样按“拉直该处国界”作为某年起的变化。交汇节点（连接多条边界）在此模式下拒绝拖动，提示改用“重画国界”。海岸上的点同样适用（向海一侧为新增陆地，向内为变为水域）。

### M4 第六步：整理地块；重画预览面积与提交一致（2026-10-30）
- [x] 按年份修改边界（重画国界、按年份拖动顶点、按年份绘制）会把土地切成只在某些年份不同的地块；切分后未改归属也会留下碎块。“编辑 → 整理地块”（`Document::tidy_faces`）合并所有在每个年份、每个分区层（含比例层）、海陆历史都完全相同的相邻地块，反复进行直到没有可合并的。合并条件即 `same_history`，所以任何年份的地图都不会改变；每次合并在副本上尝试，失败不留半合并状态；没有可合并时不进入撤销历史。
- [x] 重画国界的预览改为与提交时同样沿屏幕直线加密后再计算，预览面积即实际移交面积（此前相差约 0.3%）。

- 测试：两国方块先做两次未改归属的切分，再在 1950 年重画国界，整理后合并 ≥2 处、拓扑有效，1900、1949、1950 与无年份视图中陆地与各国面积不变；1950 年移交的区块与两侧在 1949 年历史不同，保持独立；再次整理为 0。界面验证（示例世界，1900 年）：重画国界预览“约 1,503,622 km²”，提交后“从沙洲联盟取得 1,503,622 km²”完全一致；切分白鹭国（地块 16 → 17）后整理地块：“合并 4 处，地块 17 → 13；各年份地图不变”，1900 与 1899 年各国面积均与整理前相同，白鹭国的切分线消失，1900 年起移交的区块保留。

### M4 第七步：河流画完后可编辑（2026-10-30）
此前河流只能画，画完不能选中、修改、重命名或删除。河流是自然地理要素，不随年份变化，因此以下操作直接修改线条（均可撤销）。

- 测试（3 项）：带洞的面、多面、各类属性往返；线与长字段名、一种几何类型一个文件；无 .cpg 的 GBK 属性按内容识别，投影坐标被拒绝。另用独立实现 pyshp 3.1.6 核对：读取示例世界导出的三个 Shapefile，几何类型、带湖国家的内环、多面与中文属性都正确；pyshp 写出的 GBK、PolygonZ（带洞）与空记录由本程序正确读取；示例世界导出再导入后 11 个国家面积完全一致。界面验证：从菜单导入 pyshp 写出的 GBK 文件为独立岛屿，新增 3 个面、2 个国家，“河谷王国”名称正确、洞为湖泊，撤销恢复。
- 时间轴：拖动时每帧只按最新年份更新一次（立即模式界面，没有积压的请求）；地图、标题与图例在应用与各类导出中都取自同一个年份视图（导出先复制文档、设定年份，再由同一文档生成标题与图例）。

### M4 第三十八步：测试世界与长历史下的性能（2026-11-06）
- [x] 测试世界（`map_core::testworld::history_world`，文件菜单“新建测试世界（多层、长历史）”，后台生成约 2 秒）：网格大陆加跨日界线的岛国，1000–2000 年间用作者同样的操作做出 240 次变化——相邻国家夺取边界地带、海岸扩张与新湖、建国（带成立年份）与终止（带后继、领土从次年起交给后继）；每 50 年的人口记录（插值）；城市的上级随所在土地逐年记录；文化区独占层（自身也有变化）、宗教比例层；河流、商路、海名、带年份的战役符号与争议区。规格可调（`TestWorldSpec`），同一规格结果完全相同。测试：拓扑有效、每个抽样年份的归属实体都存续且“需确认”为空、可复现。
- [x] 基准（`map_bench history [nx ny 变化数]`，结果见 BENCHMARKS.md）。证据：
  - **几何多版本暂不需要**：1000 次变化后面数从 240 增到约 6200（历史把地块切碎），但切换年份仍是逐面一次的轻量计算（平均约 14 ms，最慢约 42 ms）；整理地块几乎合并不了（碎块的历史确实不同）。
  - **按年份绘制是真正的瓶颈**：原先选定年份时局部重建一律退回整体重建，6200 面时一次边界修改约 850 ms。
- [x] 局部重建支持年份（`overlay::apply_local`）：选定年份时，只在陆地之间易手（夺取 / 扩张、多边形不触及海和湖）时局部拼接；新块沿用来源面的归属与海陆历史，变化从该年记录（与整体重建同一个 `adopt_owner_history`）。布尔运算留下的“新陆地”碎屑（几百平方米，小于所画面积的百万分之一）不算新陆地；真正涉及海陆的按年份修改仍整体重建。
- [x] 拼接的两处健壮性修正：（1）有年份时海被保留为多块不同历史的水面，局部结果中的一个水域可以同时挨着几块未动的水面（只有新水域与已有水域相连才退回）；（2）布尔运算会去掉与直线相差约 1e-8° 的顶点，使重建出的海岸跨过原有的结点、一条边同时挨着海和一个窄面——现在先把冻结边界上的结点重新插回所在线段（`repair::insert_anchors`），并按边上最长的一段判断两侧所属面。
- [x] 各年统一分级：面的面积在各年份中不变，只计算一次；年份分到各核并行。
- 结果：10×6 / 240 次变化，1990 年画一条边界 79 ms → 3.4 ms（只重建 2 个面），生成 11.9 s → 1.9 s，统一分级 255 ms → 10 ms；20×12 / 1000 次变化，同样的修改 850 ms → 13 ms，统一分级 5.3 s → 95 ms，1142 次绘制中 1026 次局部。

### M4 第三十九步：按年份的海陆修改局部重建；精细边界与百万三角形（2026-11-06）
- [x] 按年份的海陆修改也局部拼接：选定年份时局部路径与整体重建使用同一套“显式块”（`overlay::emit_explicit`，只对多边形附近的面计算）——每个被覆盖的面（陆地或水面）切成内外两块，多边形下的海作为以海为来源的块；每块沿用来源的海陆与归属历史，再从该年记录新的海陆与归属。因此海变陆在该年之前仍是海，挖出的湖在该年之前仍是陆地，且不会并入相邻的海。没有覆盖到的空隙（理论上不应出现）退回整体重建。
- [x] 测试世界可细化边界（`TestWorldSpec::refine_km`、`testworld::refine_borders`）：历史生成后，每条边逐段二分，中点侧移最多为该段长度的 18%（只对短于 2° 的段，保持大尺度形状），直到每段约为指定长度；会与其他边相交时先降低起伏，最后只沿原线加密（不会相交）。菜单新增“新建测试世界（精细边界，约百万三角形）”（3 km，约 40 万顶点、97.5 万三角形）。
- [x] 大图上的三处瓶颈（由基准与应用内分段计时发现，`ATLAS_PROFILE` 环境变量在状态栏显示“派生 / 面板 / 视图 / 其余”耗时）：
  - **线段邻近查找**：新的 `seggrid::SegGrid`（按数据的平均段长定格子大小、每段只登记它穿过的格子、扁平数组而非哈希、经度跨日界线回绕），用于修复时的吸附（`repair::snap_points`，含冻结结点插回）、批量的“编辑会导致边界相交”检查与局部校验的相交查找。细化 125 万顶点从 22.5 s 降到约 4.7 s；1 km 世界上一次局部编辑的两次吸附从 170+126 ms 降到 68+59 ms。
  - **面积**：国家列表每帧对所有面重算球面面积（40 万顶点时每帧 13 ms）。面积现在按几何版本号全进程缓存（版本号从不复用）；读取工程时为每个面分配新的版本号——此前从文件读入的版本号可能与本次运行中另一个文件的相同，按版本号缓存的三角化也可能因此混淆。

### M4 第四十步：日界线处的重建失败（2026-11-06）
- 现象：在测试世界跨日界线的岛国附近按年份修改，整体重建报“边界相交（约 −180°）”，同一次修改局部路径成功；局部也退回时修改会被拒绝。
- 原因（两处，都来自布尔运算的舍入）：（1）切出的块在日界线上的顶点被舍成 180.0000000007、−179.9999999999 等，重建时按经度回绕，180.0000000007 变成 −179.9999999993，块跳到地球另一侧；（2）被重新切过的块，其日界线顶点的纬度与未切的相邻块差约 1e-9°，而重建时的顶点聚合把 +180 与 −180 当作相距很远，两侧不会合并，回绕后成为两条几乎重合、互相穿过的边。
- [x] 修正：布尔结果中距 ±180° 不到 1e-7° 的经度放回日界线上（`overlay::on_seam`，保持所在一侧）；重建前把日界线上（两侧）相距在容差内的纬度对齐（`repair::unify_seam`），优先用局部重建中冻结结点的纬度，否则用最多块共有的值（未切相邻块保留的精确值）。
- 测试：`overlay_years` 中按年份的海岸修改改为严格比较——整体重建失败即测试失败（之前跳过）；40 次全部通过，其中 39 次走局部（剩下 1 次在北岸 72°N，局部校验发现背景环方向异常后安全地整体重建，与日界线无关）。修正前同一组修改中有 1 次整体重建失败、2 次局部因日界线退回。

### M6 第二步：封闭海峡时的拓扑无效（2026-11-10）
- 现象：深度压力测试第 19 组种子第 1948 步，一次按年份的"扩张"返回成功，全量校验却报"背景面的洞不是顺时针"。约 9.4 万次随机操作中出现 1 次。
- 原因：新陆地画在海峡口上，把一片原与外海相通的海围成了内海。局部重建重新组装背景面的环时，把内海的岸线也当作背景的洞收下；但背景面不能有被陆地围住的孤立部分，内海必须是独立的水面。这一圈岸线全是未改动的旧边，而局部校验只检查含新边的环，所以漏过。未选年份的局部重建有同样的问题。

### M7 第三步：图层面板（2026-11-12）
- [x] `map_core::stack`：要素的图层（代码里叫 group，因为 `layers` 已指国家、文化等分区层）。一个图层是一组绘制要素（地图文字、符号、河流与线路、斜线区域），有名称、显隐、锁定、不透明度，图层之间有上下顺序；一个要素至多属于一个图层。**不在任何图层里的要素最先绘制、顺序与以前完全相同**，然后各图层自下而上，所以没有图层的旧工程外观不变（`Document::groups` 与 `group_of` 为 serde 默认，旧文件读出为空）。
- [x] 隐藏的图层：其中的要素不绘制、不导出、不进图例，也不参与地图上的拾取与吸附（`group_hides`，各处与要素自己的 `hidden` 一并判断，要素自己的开关不被改动）。锁定的图层：照常显示，但不能在地图上选中或移动（`locked_in_effect`、`pickable`）。再制的要素留在原要素的图层里；删除要素时一并离开图层。
- [x] 应用里的绘制（`draw_passes`）：逐遍绘制，每遍是一个图层的区域、线路、文字、符号，整遍按图层的不透明度变淡（egui 画笔的不透明度）。图层里的河流也在自己那一遍里绘制；不在图层里的河流仍随底图由 GPU 绘制。
- [x] 导出（`map_io::scene`）：每个图层单独成组（`SceneLayer`：底色、线、填充形状），依次盖在原有内容之上，不透明度写进颜色；图层内要素的文字随图层变淡。SVG 中每个图层是一个带名称的 `<g class="layer">`。没有图层时场景与原来逐项相同，PNG 逐像素一致。

- [x] 查询接口 `features.list` 每项多出 `layer`（所在图层的名称或 null），`shown` 计入图层的显隐。
- 界面验证中发现并修掉的两个旧问题：
  - **文本框里的 Ctrl+A、Ctrl+Z、Ctrl+Y 同时触发地图的全选、撤销、重做**。现在文本框有键盘焦点时这些键只属于文本框。

### M7 第四步：曲线与钢笔工具（2026-11-13）
- [x] `map_core::curve`：河流、线路、斜线区域可以是贝塞尔曲线。曲线 = 锚点列表，每个锚点至多两个控制柄（绝对坐标）；两锚点之间是经纬度平面上的三次贝塞尔曲线（与所有线条同一个平面，跨日界线走短的一侧），两侧都没有控制柄的段是直线段。
- [x] **曲线是源，点是派生的**：要素的 `pts`（区域的 `ring`）总是曲线的细分结果（自适应 de Casteljau，容差为该段控制多边形长度的 0.2%，限制在 1e-5° 到 0.02° 之间）。因此绘制、导出、长度、拾取、吸附、沿线名称、图层与查询接口都不用改。曲线存在 `Document::curves`（按要素 id 的旁表，serde 默认，旧工程不变）。
- [x] 一致性规则：直接改点的操作（删除河流点、编辑区域点、区域布尔运算、延长线、平滑/自然化、`set_line_points` 等）调用 `points_changed`，要素变回普通线且形状不变；移动、旋转、缩放、复制同时变换曲线并重新细分（平面贝塞尔曲线在球面旋转下不是不变的，不能直接旋转细分点）；删除要素时删曲线；剪贴板带曲线（`Clip.curves`，旧剪贴板文本可读），拖动时每帧从原样恢复也包括曲线（`set_feature_from`）。
- [x] 钢笔工具 P：选项栏选画河流、线路或斜线区域。单击放尖角锚点，按住拖动放平滑锚点并对称拉出控制柄，画区域时单击第一个锚点闭合；双击或回车完成，右键或 Backspace 撤回，Esc 放弃。没有在画时单击线或区域即选中它。
- [x] 锚点与控制柄编辑（选择工具选中一条曲线、钢笔工具点选、或编辑顶点工具）：拖动锚点（控制柄随之平移）或控制柄（平滑点的另一侧保持反向），Alt 拖动控制柄拆成尖角，双击锚点切换平滑/尖角，双击线上添加锚点（形状不变），右键锚点删除。每次拖动是一步撤销；拖锚点优先于整组移动与平移。编辑顶点工具不再显示曲线细分出的点。
- [x] 面板：线与区域的面板中有“曲线”一节：全部平滑、全部尖角、转为折线；普通线与区域可“转为平滑曲线”（经过现有点的 Catmull-Rom 曲线）或“转为曲线（保持形状）”（每点为尖角锚点）。
- 测试：`map_core/tests/curve.rs` 6 项；压力测试加入曲线操作类别与不变式“曲线要素的点恰为曲线的细分”。界面验证与限制详见 `HANDOVER.md` §10。全部 242 项测试通过；深度压力测试 64 个种子 × 1500 步（70,305 次操作成功、21,017 次被正当拒绝）无问题。
