# Atlas Forge 性能录制

## 在创作时录制

1. 打开「工具 → 性能检测…」。创作工作室可从「所有命令 → 工具」进入。
2. 选择「开始录制…」和新的 JSONL 文件。关闭检测面板后仍会继续录制。打开要检查的工程，按平时的方式操作。
3. 遇到卡顿时，在编辑器窗口内按 **F8**，也可在面板中标记。报告保留标记时间，自动回查前 10 秒，并列出可能对应的交互长间隔和界面慢帧。
4. 选择「停止并生成报告」。也可正常退出编辑器结束录制。组件在后台保存原始日志，生成同名 HTML 报告。

打开 HTML 可以按时间范围筛选曲线、勾选阶段、定位慢帧和标记。操作表汇总整段数据。需要进一步诊断时，一起保留 JSONL、HTML 和可以复现的操作描述。

## 命令行

将 atlas-perf 与 atlas 可执行文件放在同一目录。路径包含空格时加引号。

~~~powershell
.\atlas-perf.exe record "large-world-test.jsonl" "large-world.atlas"
.\atlas-perf.exe report "large-world-test.jsonl" "recovered-report.html"
~~~

启动录制会运行编辑器，打开工程前开始采样。工程参数可省略。正常关闭时，编辑器先关闭窗口，再并行收尾日志、报告和保存任务。退出日志含关闭窗口和释放界面资源的耗时。遇到意外退出，可从仍然存在的 JSONL 生成报告。工具按行写入，定期刷新，跳过无法恢复的残缺记录，并报告缺少结束记录或队列丢帧。现有日志和报告不会被覆盖。

## 指标与适用范围

- 界面帧记录每次应用界面更新的 CPU 耗时、从上一次更新到这一帧的间隔、输入事件类型及数量、视图、工具、地图负载和主要阶段耗时。事件驱动的界面有空闲间隔。报告另列输入集中到达、拖动或缩放期间的长间隔，并标出人工标记与候选帧之间的时间差。
- 绘制回调细分二维地图和三维球体的 CPU 侧准备和命令编码。系统采样独立记录 CPU、常驻内存、进程 I/O。Windows 在系统提供计数器时还显示进程提交内存、最忙的进程 GPU 引擎利用率、专用和共享显存。进程 CPU 占满一个逻辑核心等于 100%。
- 额外记录编辑器初始化、工程载入和保存、命令、常见后台工作与导出。异步操作可能与帧同时发生。资源约每秒采样一次，短促的资源峰值可能落在采样之间。Windows 的原生窗口重绘时间覆盖界面、图形提交及窗口等待。逐帧 GPU 执行和最终呈现需要系统图形跟踪。
- 原始日志不写入工程路径、工程名称、输入文本、按键内容、鼠标坐标、文档内容或 API 凭据。日志包含软件版本、进程号、显卡名称、时间、操作类别与工程规模。报告在本地浏览器离线打开。


Windows 启动时会优先在同级兼容显卡上选择 Direct3D 12。已有 WGPU_BACKEND、WGPU_ADAPTER_NAME 或 WGPU_POWER_PREF 环境变量时沿用原先的适配器选择流程。关闭窗口后，进程会等之前已开始的写入完成。
