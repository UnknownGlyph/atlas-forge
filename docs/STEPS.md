## M11 续——模型从零创建世界（Gemini 与 DeepSeek 各一次）（2026-11-17）

**做了什么**

- **创建用的工具**（草稿上，MCP 与助手共用，工具共 26 个）：`edit_draw_land`（多边形内的海变成陆地；给 country 时归该国，否则为无主陆地；`DrawIntent::Expand` / `AddLand`）、`edit_draw_lake`（`CarveWater`）、`edit_add_river`。
- `Session::from_arg` 支持 `--blank`（空白世界，半径 6371 km）；`atlas-agent` 加 `--turns N`（最多轮数）。
- **思考强度的取值**（实测接口校验）：Gemini 的 `thinkingLevel` 接受 "max"（未知值返回 400，所以 max 是有效级别）；DeepSeek 的 `reasoning_effort` 可取 none、minimal、low、medium、high、xhigh、ultra、max（未知值返回 422 并列出这些）。两次测试都用 max。

**实测**（同一句短提示："从零开始创造一个架空世界：几块大陆、若干国家（各有领土）、城市、河流，并写一段简短的历史（时间轴事件）。"；空白世界，最多 60 轮；密钥经环境变量，临时文件用后删除）：

| 模型 | 用时 / 轮 / 调用 | 结果 |
|---|---|---|
| Gemini gemini-4-hydrogen（max） | 260 s / 26 / 163，失败 4 次 | 3 块大陆 + 群岛、8 国、15 城、7 条河、2 个湖、海路与海洋名；历史 100–310 年：日霜之战（220 年割地约 230 万 km²）、280 年南溟分治（星辰议会成立），设置了存续期；中途放弃一次草稿重做 |
| DeepSeek deepseek-flash（max） | 139 s / 9 / 61，失败 0 次 | 4 块陆地、9 国、11 城、5 条河、5 处海名、商路；历史 1–1350 年 10 个事件、7 次领土变更（建城、分离、独立、条约）；核对：拓扑有效、无无主陆地、城市都在本国内 |

对比图：`docs/ai_create_from_nothing.png`（各自的最新状态）。

**观察**：
- Gemini 的 4 次失败都是 `edit_transfer` 的"重建拓扑失败：重叠"：它用整度数的顶点画陆地，再沿经线切分，切线经过已有顶点时触发叠加运算的已知稳健性问题（§11）；它放弃草稿后换了画法完成。
- 两边的海岸都是粗糙的多边形、国界是直线（划转按经纬线切）——工具只接受多边形与经纬线；可加"把海岸变得自然"的工具（分形细化，`refine_borders` 已有）。
- Gemini 的世界导出时 8 个国名只显示了 2 个：国土较小且挤满城市名与河名，导出的国名避让把它们去掉了（应用内与导出的标注避让问题，§11）。
- DeepSeek 一轮里并行调用多个工具，轮数少得多。

**测试**：全部 314 项通过（`tools\check.cmd` 全绿）。新增 `map_api/tests/edits.rs` 的 `a_world_from_nothing`（空白世界：建国、画陆地归该国、无主陆地、湖、河、城市；原世界仍为空白）；`mcp.rs` 工具数 26。

## M11——AI 共同创作：草稿上的编辑、MCP 写工具、助手（Gemini 与 DeepSeek 实测）（2026-11-17）

**做了什么**

- **领土划转**（`map_core::transfer`，`Document::transfer_land(from, to, area)`）：把 from 在所选年份的土地与一个范围求交，各块连同洞以"取得"写入 to（从所选年份起）——只动 from 自己的土地，不动海、湖与第三国。
- **草稿与编辑**（`map_api::edits`，阶段 C）：`Session` 增加 `draft` 与编辑记录；`handle_mut` 处理 `edit.*`、`draft.*`，其余照旧。编辑只改草稿（第一次成功的编辑时从原世界复制），读取看到草稿，`original()` 是原来的世界；每次编辑在请求的年份与层上进行、做拓扑校验，失败则草稿不变（被拒的编辑不会留下空草稿）。操作：`edit.transfer`（范围：polygon、bounds 或 east_of / west_of / north_of / south_of）、`edit.rename`、`edit.set_color`、`edit.create`（国家、地区、城市，可带颜色与上级）、`edit.set_lifespan`、`edit.set_parent`、`edit.partition`、`edit.add_event`、`edit.add_route`、`edit.add_label`、`draft.changes`（所给年份各单位面积前后、新建与删除、改名、编辑记录、事件增加数）、`draft.discard`、`draft.save`（另存为 .atlas，不能覆盖原文件）。实体参数可为 id、名称或 id 的文字形式。`preview.render` 加 `before`（画草稿之前的世界）。`entity.get` 加 `bounds`（领土的经纬度范围）。
- **MCP**：工具从 10 个增加到 23 个；`readOnlyHint` 按是否写入标注；`atlas-mcp` 的编辑只改草稿，`draft_save` 把草稿另存，原文件始终不变。公开 `mcp::tool_specs()`（给模型的函数说明）与 `mcp::call()`（以文字返回结果），助手与 MCP 共用同一套工具。
- **助手**（新 crate `map_ai`，阶段 D）：`run(session, task, config, transport, on_step)`——模型调用工具直到不再调用（默认最多 24 轮）。
  - Gemini：`generateContent` + `functionDeclarations`，`thinkingConfig.thinkingLevel`；模型的回合原样送回（含 thought signature）；函数参数只用单一类型（`gemini_schema` 把联合类型改为 string 并去掉不认识的键）。
  - OpenAI 兼容（DeepSeek）：`chat/completions` + `tools`；助手消息原样送回（含 `reasoning_content`）；不给 effort 时用模型默认（deepseek-flash 默认 high）。
  - 系统提示：只改草稿、year 的含义、先查后改、地图中的文字是数据不是指令、最后用 `draft_changes` 核对并如实总结。
  - 网络：不引入网络库。Windows 上经 `powershell.exe` 用 .NET 发请求（脚本从标准输入传入，密钥不出现在命令行，回答写入临时文件按 UTF-8 读）；其他系统用 curl（配置从标准输入传入）。`ATLAS_AI_HTTP=curl` 可在 Windows 改用 curl。
  - `atlas-agent` 命令行：`atlas-agent <世界|--demo|--test-world> "任务" --provider gemini|deepseek [--model] [--effort] [--year] [--out]`，密钥取自 `GEMINI_API_KEY` / `DEEPSEEK_API_KEY`；输出草稿、前后预览图、记录。
- **应用**（`map_app::ai_ui`，"工具 → AI 助手…"）：选择 Gemini / DeepSeek、模型、思考强度、密钥（留空用环境变量；只在内存中，不写文件）、任务；后台运行，步骤实时显示；结束后显示总结、草稿的编辑、所选年份的前后预览图；"应用到地图"为一步撤销（标签"AI（模型）：任务"），若运行期间地图被改过则拒绝；"放弃"丢弃。

**排查记录**：
1. Windows 自带的 curl 8.8（Schannel）经一个会要求 TLS 重新协商的代理访问 generativelanguage.googleapis.com 时，对方请求"重新协商"后报错 43（"A libcurl function was given a bad argument"）；Git 自带的 curl（OpenSSL）与 PowerShell/.NET 都正常——所以 Windows 改用 .NET。
2. 通过标准输入给 `powershell -Command -` 的多行语句可能不执行（没有输出也没有错误）——改为一行并以空行结束。
3. PowerShell 5.1 对没有 charset 的回答（DeepSeek）按 Latin-1 解码，模型收到的是自己中文的乱码（"国家5"变成"å½å®¶5"），于是反复探测、放弃草稿；改为按 UTF-8 读取原始字节后正常。
4. 两个模型都因为没有办法得到国家的经度范围而用 `place_at` 逐点探测（56–103 次），因此给 `entity.get` 加了 `bounds`（加入后未再实测）。

**实测**（密钥经环境变量传入，未写入任何文件；每个模型完整测试一次）：任务"从 1800 年起，把一个国家东半部（以它 1800 年领土的经度中线为界）划给东侧邻国，并加一个 1800 年的事件；先查清现状，最后核对"，在测试世界上：
- **Gemini gemini-4-hydrogen（思考 high）**：194 s、23 轮、103 次调用。选国家5（经度 -61.52°～-26.24°，中线 -43.88°），东半部 2,867,351 km² 划给国家6；加了事件；用 `draft_changes` 核对 1799 年无变化、1800 年符合预期，`checks_run` 拓扑正常。
- **DeepSeek deepseek-flash（默认 high）**：（修正编码后）132 s、22 轮、95 次调用。选国家4（-94.2°～-58.3°，中线 -76.25°），2,888,724 km² 划给国家5；加了事件；核对 1790、1800、1830 年。
- 前后对比图：`docs/ai_test_1800.png`。
- 应用内的 AI 助手窗口：打开、界面与设置正常；**没有在应用里跑完一个任务**——自动化输入被系统的中文输入法拦截（剪贴板粘贴未生效、按键进入拼音），助手的逻辑与命令行用的是同一个 `map_ai::run`。

**测试**：全部 313 项通过（`tools\check.cmd` 全绿）。新增：`map_core/tests/transfer.rs`（东半部划给邻国：只动给出方、湖与第三国不变、更早年份不变、范围内无其土地时拒绝）；`map_api/tests/edits.rs` 2 项（经 MCP 工具：划转、读取看到草稿而原世界不变、1799 无变化、改名新建事件、前后预览、另存且不能覆盖原世界、放弃；被拒的编辑不留草稿）；`mcp.rs` 更新为 23 个工具与只读标注；`map_ai` 单元测试 3 项（用脚本化的传输：Gemini 调工具改草稿、thought signature 原样送回、思考等级、单一类型的参数；OpenAI 兼容调工具、reasoning_content 送回、tool 消息；没有密钥时报错）。

## M8 第四步——三百万三角形下的帧时间：国名按固定字号阶梯排版（2026-11-16）

**测量方法**（新增，供以后用）：`map_bench history 10 6 240 1`（边界细化到约 1 km）加 `ATLAS_BENCH_KEEP=1` 保留生成的世界（文件位置见命令末行，2 574 312 个三角形，1 244 691 个顶点，840 个面）；应用以 `ATLAS_PROFILE=1` 启动时，每帧在标准错误输出 `FRAME ui … derived … panels … views … rest … dt …`、每个视图的 `OVERLAYS`、平面图叠加层的 `PARTS features … line_names … countries …`（不设该变量时不输出）。在应用里反复缩放后对这些行求平均与最大值。注意：状态栏的"帧 / UI"是平滑值，应用空闲不重绘时停在最后的数上（加载那一帧的 795 ms 会让它显示 37 ms 很久），不能当作当前帧时间。

**发现**：应用一帧的 CPU 时间平均 12.8 ms、最慢 75 ms，其中视图的叠加层占大头；叠加层里国名平均 5.9 ms / 视图、最慢 21 ms，要素 0.25 ms、线名 0.05 ms。原因：缩放时每个国名的合适字号每帧都不同，egui 对每个新字号都要把字形重新栅格化并放进字形图集（图集也越长越大）。

**做了什么**（`map_app::label_ui`）：
- 国名按固定的字号阶梯（相邻差 8%，`quantised`）排版，再把字形四边形按"想要的字号 / 阶梯字号"缩放到实际大小（最多 ±4%，看不出来）；字距按同一比例换算。缩放时字号落在已有的阶梯上，字形不再重新栅格化。`bend` 多了缩放参数；`Laid.galleys` 带上各自的缩放。
- 自动国名在排版前先看它的线是否靠近视图（`line_near_view`：线上 8 个点的外框按线高放大），不在附近的不排版。

**结果**（同一世界、同样的缩放操作）：国名平均 5.9 → 0.59 ms / 视图，最慢 21 → 2.1 ms；整帧 UI 平均约 8.5 ms（派生数据 0.01、面板 1.0、视图 7.4）；最慢的几帧（约 20 ms）是加载后或空闲后的第一帧。GPU 绘制时间应用内测不到，未单独测量。

## M9 收尾——道路与旅行、按文化的名称风格、划分与层级的修复（2026-11-16）

这一步做 M9 的剩余部分（Linux、macOS 暂缓）。

**做了什么**

- **道路与旅行**（`map_core::roads`，`map_app::roads_ui`，"工具 → 道路与旅行…"）：
  1. 候选：每座城市与最近的几座（"相邻城市"，默认 4）。
  2. 路径：在覆盖所有城市的网格上（约 16 万格，四周留出城市分布范围的 40%，好绕过湖泊、沿海岸走）做 A*（八邻）。陆地按扫描线把每个陆地面的环（含洞）偶奇填充到网格上，比逐格查面快得多。代价 = 距离 ×（1 + 12 × 坡度）（地图有地形且勾选"陡坡代价更高"时）；紧挨水的格子再 ×1.3，道路离岸一点。城市在海岸线上时先移到附近 3 格内的陆地。
  3. 网络：按路径代价做最小生成树（Kruskal），再按代价从小到大加"捷径"：沿已有道路的路程比这条长出"捷径"倍数（默认 1.6）时加入。
  4. 路线：Douglas–Peucker 简化（0.6 格）再 Chaikin 平滑；平滑或简化后若有一段进了水（绕湖拐角处会切进去），依次退回只简化、原始格子路线。
  5. 写入：`apply_roads` 把每条路写成普通线路（名称"甲城—乙城"，图例"道路"，棕色实线；所有年份相同），一步撤销。窗口里应用后显示"已应用"，不再提供同一组道路（撤销后又可应用）。
  6. 旅行：`travel_way(a, b)` 沿地图上的线路（两端在城市位置上的线路：生成的道路、吸附到城市画的线路）求最短路（Dijkstra），返回经过的线路与公里数；窗口选起点终点后显示路程、直线距离和各种方式的天数，并在地图上高亮所走的线路；不连通时按直线估算（含帆船，仅供参考）。
  7. 天数：`MODES` 每日行程——步行 30 km、车队 25 km、骑马 60 km、驿马（换马）200 km、帆船 150 km；不足一天按十小时折成小时。测量工具（未闭合时）和所选线路的面板也显示各方式的天数。
- **按文化的名称风格**：文档旁表 `Document.name_styles`（`EntityId → NameStyle`，serde 默认空，旧文件照常读）。`set_name_style`；`name_style_for(e)`：自己的风格优先；否则在其他分区层里找设了风格的单位——城市取它所在的面，国家/地区取它（含下级）大部分国土所在的单位。属性面板每个单位有"名称风格"一行（没有自己的风格时显示"随所在：…"）。"随机"名称、自动划分窗口的默认风格、名称生成器（提示"改用它"）都随之。删除单位时清掉它的风格。`NameStyle` 加了 serde 派生（按名称存）。
- **划分与层级的修复**（上一步记录的复杂世界中的失败）：
  - **合并造成的"自己是自己的上级"**：`map_parents`（合并、删除单位时改写所有年份的上级）在"A 的上级是 B、把 B 并入 A"时让 A 成了自己的上级，此后任何单位都不能再放到这棵树下（划为省时报"这会使一个实体成为自己的上级"——上一步未查明的原因就是这个）。现在映射到自身的上级去掉；隔一层的情形（A→C→B，B 并入 A 成了 A→C→A）由 `break_cycles_through` 去掉 A 那条回到自己的上级。读文件时 `drop_self_parents` 清掉旧文件里已有的自环。压力测试加了不变式"没有单位是自己的祖先"。
  - **极地国家**：划分时国土在平面上沿极线闭合，各块的环带着极点上的点，显得自相交；现在去掉极线上的点（在球面上就是环绕极点的环），面积仍按平面计算。叠加运算的 `prepare_with_holes` 支持环绕极点的外环带洞（洞不能环绕极点）；`ring_planar` 把两种准备共用的部分抽出。
  - 国土的各块先合并（`union`）再与网格求交：跨日界线的国家在平面上是沿 ±180 相接的几块，以前各单位的块会停在这条线上。
  - 结果：上一步保存的 39 个失败案例中 5 个变为成功（3 个层级、2 个日界线）。其余多为叠加运算在极点与日界线附近的重建失败（"FaceId(0) hole is not clockwise"、在 ±180 处"边界相交"），属于叠加运算本身的问题，留作后续（见 §11）。

**测试**：全部 300 项通过（`tools\check.cmd` 全绿）。新增：`map_core/tests/roads.rs` 3 项（生成世界的道路网：两端在城市、中间点九成以上在陆地、不短于直线、写为线路且一步撤销、沿线路的最短路不长于最长那条路本身；两个岛之间没有路且孤岛城市列出；湖的两侧城市的路绕湖且比直线长 10% 以上；天数）、`roads` 单元测试、`map_core/tests/name_styles.rs`（文化把风格借给大部分国土在其中的国家和所在城市、自己的风格优先、删除单位后风格随之消失）、`map_io/tests/name_styles.rs`（保存读回；旧文件为空）、`timeline.rs` 的 `merging_never_makes_a_unit_its_own_ancestor`（直接与隔一层两种合并）。深度压力测试（64 种子 × 1500 步，含新不变式）：73247 次操作应用、21777 次被拒绝，没有问题。

**调试记录**：道路网起初在生成世界上要 15 s——A* 的估价用两端纬度的平均余弦缩放东西距离，经过更高纬度的路其实更短，估价偏大，格子被反复打开（一次搜索弹出 6800 万次）；改用网格最高纬度行的余弦（永不偏大）后降到 68 ms。另外最初的边距只有分布范围的 8%，绕湖所需的格子不在网格里，湖两边的城市连不上。

**界面实测**：向导生成世界（24 城）→"道路与旅行"：预览"24 座城市，28 条道路，共 86293 km；无法经陆路连通：镇门"，棕色虚线；应用后成为棕色线路，窗口显示"已应用"，Ctrl+Z 后又可应用。旅行"丹州 → 柏江镇"：沿线路 6509 km（2 段；直线 6046 km），步行约 217 天、车队约 260 天、骑马约 108 天、驿马约 33 天，地图上黄色高亮。示例世界北原王国"名称风格"设为拉丁字母后"随机"得到"Falonor"。文化把风格借给城市与国家只由自动测试覆盖。

## M9 第四步（M9 完成）——自动划分（新国家或省）、国名覆盖整个层级、同种子同世界（2026-11-16）

**做了什么**

- **自动划分**（`map_core::partition`；`Document::partition_plan(e, &PartitionSpec) -> TResult<Plan>` 只计算，`apply_partition(&plan, &spec) -> TResult<Vec<EntityId>>` 写入）：
  1. 国土溶解成多边形，各块的经度规整到最大一块附近（跨日界线的国家不被切开），铺在细网格上（格边长 = √(面积 / 20000)，约两万格）。勾选"尽量沿河流与山脊"时标出河流经过的格子，并取各格高程（文档有地形时）。
  2. 种子：按连通的陆块分配份额（先按面积下取整，余数给"每个种子分到的土地"最多的陆块），陆块内用最远点采样分散。分不到种子的小岛记下来，生长结束后归入最近的单位。
  3. 生长：多源 Dijkstra。跨河每步加 8 格的代价，坡度乘 (1 + |Δh| / 150)。勾选"大致均衡"时做 28 轮：前 4 轮把种子移到各单位重心（Lloyd），之后按 (大小 / 平均)^0.6（第 14 轮起 ^0.3）调各单位的生长权重，保留最均衡的一轮；不要求均衡时只做 5 轮 Lloyd。
  4. 被围住的空格用广度优先补上，网格外的格子归最近的单位；各单位的格子追踪成环（`BTreeMap`，结果可复现），再与国土求交，得到严格沿原国界的多边形和面积。求交会把坐标舍入一点：离网格线 1e-7° 以内的角点放回网格线上（与追踪同样的算式），两个单位共用的边界在两边完全相同。在某个角点自相接触的环拆成简单环（`simple_loops`；外环里反向的那个环是贴着外环的洞）。每块是 `Part { outer, holes }`：洞是别的单位、湖泊或他国飞地。
  5. 中等国家划 6 块约 0.35 s。面积比（最大 / 最小）多在 1.25 以内；有大岛或细长半岛时个别可到 2 左右。没有领土、单位数超过网格容量时返回错误说明；应用失败时提示"换一个方案或改变单位数"。
- **应用**（一步编辑，可撤销）：
  - 新国家：原国家保留第一块（在最大的陆块上），其余成为新国家。名称由名称生成器按所选风格起，不与已有名称重复；存续期同原国家；自动配色，相邻不同色。
  - 下级地区（省）：全部成为原国家的下级（`Region` 名称，`parent` = 原国家，从所选年份起记录），原国家不再直接拥有地块；零碎的剩余地块按最长公共边归入邻近单位。
  - 各块**连同它的洞**按面积从大到小以"取得"写入（`overlay::apply_with_holes`）：选了年份就从该年起生效，更早的年份不变；洞里的湖泊、他国飞地、别的单位都不动。（最初只画外环："取得"会把多边形里的水变成陆地、把别国的土地拿过来，所以国家里的湖被填平、飞地被吞掉。新测试证明了这一点：不带洞时 18430 km² 的湖变成 0。）
  - 新出现的内部边界用 `worldgen::smooth_line` 平滑（节点不动；平滑后会相交的边保持原样）。**只平滑划分本身在某个面里画出的线**：两侧除了本次的单位以外历史完全相同（`Document::same_past`：所选年份之前的归属、陆地或水域、其他分区层与比例层）。最初两个单位之间的所有边都平滑，其中包括旧边界（更早的年份里分隔着别的国家或水域），深度压力测试发现这会改变更早年份的面积（66 km²、215 km²）。
- **国名覆盖整个层级**：`label_path` 对有上级的实体返回 `None`；顶层实体的名称线按它和全部下级的土地计算（`Document::faces_of_tree`）；`LabelCache::update` 把受影响实体的顶层上级（变化前、变化后都算）一起重算；导出场景跳过没有手动名称位置的下级。所以划成省之后，政治地图上仍只有一个国名，省界按已有的"内部边界"样式画成淡线（`tess::edge_class` 按顶层上级区分国界与内部边界，本来就是这样）。
- **界面**（`map_app::partition_ui`）：属性面板国家一栏多了"划分 / 自动划分…"。窗口"自动划分"：单位数（2–40）、划为新国家或下级地区（省）、面积大致均衡、尽量沿河流与山脊、名称风格、方案编号与"换一个方案"。设置一变就重新计算，地图上用蓝色虚线（白色衬底）预览各块；窗口显示块数、面积范围和生效年份；"应用"后状态栏列出新单位的名称。
- **叠加运算的精确坐标**（`overlay`、`repair`，所有绘制都受益）：布尔运算内核会把输出坐标舍入约 1e-8°，修复流程以前只让输出的点互相吸附（注释说"吸回运算前的精确顶点"，实际收集的却是运算后的点），所以每画一次，新边界都离所画的位置一点，被重画的整个面（即使远离所画的多边形）的边界也会漂移。自动划分沿同一条网格线先后画相邻的单位时，后画的多边形与这条略偏的边界几乎重合，留下的细缝在吸附后变成"两个多边形从同一侧使用了同一段边界"，重建失败。现在 `RepairOptions.prefer` 给出首选位置（`overlay::exact_corners`：被切的各面原来的顶点在前，所画多边形的顶点在后；彼此在吸附距离内的只留第一个，地图原有的点优先），输出顶点在吸附距离（5 cm）内就回到这些点上。极点与日界线附近（1e-6° 以内）的点不作首选位置：那里的输出已被 `at_pole`、`on_seam` 放到精确的极点与日界线上，首选点会把它拉回去（深度压力测试中一个极地冠因此变成面积为 0 的面）。
- **带洞的多边形**：`overlay::apply_with_holes(doc, outer, holes, intent)`（`apply` 即无洞的情况）：外环逆时针、洞顺时针并移到外环的经度范围；不支持环绕极点的外环带洞（返回"环绕极点的多边形不能带洞"）。
- **同种子同世界**：世界生成的轮廓追踪改用 `BTreeMap`（之前 `HashMap` 的遍历顺序会改变环的起点）。测试 `the_same_seed_the_same_world` 加强为整个文档相等，只把面的 `rev` 清零后比较：`rev` 是进程内唯一的几何版本号（面积缓存的键），同一进程里生成两次必然不同，读文件时也会重新编号，它不是内容。排查中确认：两次生成的边、节点、面的外环与洞、归属、实体、河流、地形全部一致，唯一的差别就是 `rev`。

**测试**：全部 293 项通过（`tools\check.cmd` 全绿）。新增 `map_core/tests/partition.rs` 5 项：
1. 一国划为 5 国：各块面积之和等于原国土（±2%）、最大块 < 最小块 × 2.2、应用后拓扑有效、其他国家不变、相邻颜色不同、名称不重复、撤销复原。
2. 从某年起划为省：下级的 `parent` 正确、原国家没有直属地块、国名还在（原国家有 `label_path`、下级没有、`LabelCache` 里有原国家）、主题颜色取上级的颜色、该年之前未划分。
3. 同一方案编号结果相同、不同编号结果不同、单位过多时被拒绝。
4. 一个生成世界（种子 9）的每个国家划为 10 块都成功、拓扑有效（修复前其中"广汉邦"在 (-155.12°, -51.52°) 重建失败）。
5. 国家里的湖与他国飞地在 4 个不同方案下面积都不变（不带洞绘制时湖被填平）。

另有 `overlay` 单元测试 `drawn_borders_keep_their_exact_corners`：画出的角点精确保留；同一个面在别处被重画后仍精确；沿它的一部分再画（角点落在旧边中间）成功且面积准确。**已验证这两类新测试能抓住问题**：临时去掉首选位置时第 4 项和这项单元测试都失败，临时不带洞绘制时第 5 项失败。

压力测试（`map_io/tests/soak.rs`）加了第 22 种随机操作"自动划分"（随机国家、2–5 块、随机均衡/沿河/新国家或省），年份问题现在也保存出问题前的世界。深度压力测试（64 种子 × 1500 步）：73047 次操作应用、21969 次被拒绝，没有问题（615 s；修复前同样的运行有 3 个问题：一个极地冠变成面积为 0 的面、两次划分改变了更早年份的面积）。

worldgen 与 partition 两组测试单独连跑 3 次、在整个工作区里跑多次都通过（之前工作区里出现过一次划分测试失败，原因是追踪用的 `HashMap` 顺序，已改）。

**排查记录**（给后来者）：3 个生成世界的每个国家 × 3 种设置共 213 次划分，最初 3 次失败（1.4%）。试过但无效的：把方案的角点吸到国界原顶点上（变成 5 次失败——四舍五入后的副本和原顶点同时作为吸附目标，本该重合的点被分到两处）；重建失败时改用"消除重叠"再建一次（没有变化）。逐步重放找到根源：前一步画出的边界离网格线 2.4e-8°，后一步的多边形正好在网格线上。加入首选位置并去重后 213 次全部成功，耗时 55 s（之前 57–77 s）。

**界面实测**：选中国家打开"自动划分"，预览随设置变化；以"下级地区（省）"应用后国名仍是一个，省界为淡线。示例世界"北原王国"以"新国家"模式划为 6 块（预览 189–191 万 km²），应用后列表多出 5 个国家、各约 190 万 km²，状态栏列出名称，颜色各不相同；Ctrl+Z 撤销后恢复为 1141.6 万 km² 的一个国家。这次实测用的版本已有精确坐标的修复，**还没有"带洞绘制"与"只平滑新画的线"**这两处之后的改动（它们只由自动测试与压力测试覆盖）。

**限制**：在压力测试的随机世界里（有极地大陆、跨日界线的国家、湖泊和多年历史），抽样 8 种子 × 1500 步中排除"国家当年没有领土""未选年份"后的 253 次划分：196 次成功，被拒绝的有重建失败 25 次（多在极点与日界线附近，如"FaceId(0) hole is not clockwise"）、环绕极点的块带洞 13 次、块自相交 11 次、划为省时"这会使一个实体成为自己的上级"8 次（原因未查明：`record_parent` 的检查在层级中别处已有环时，走满步数也判为环，可能是这个）。被拒绝时文档不变。生成的世界不到两极、不跨日界线，213 次全部成功。一次只显示一个方案（用"换一个方案"切换，不能并排比较）；单位由网格生长而来，边界虽经平滑仍有网格痕迹；有大岛或细长半岛的国家面积均衡较差；只能划分国家（实体），不能划分无主陆地；省没有自动名称，也没有省一级的名称样式（小字号、随缩放出现）。

## M9 第三步——新世界向导、地形与晕渲、河流生成、随机历史（2026-11-16）

**做了什么**

- **新世界生成**（`map_core::worldgen::generate(WorldSpec) -> (Document, WorldReport)`）：
  1. 半度网格（720 × 360）上的高程：球面上的三维值噪声分形（无接缝）+ 扭曲坐标 + 各大陆中心的隆起 + 脊状噪声（山脉）；在日界线附近与两极压低（陆地不跨地图边缘、不绕极点）；按面积加权的分位数定海平面，使陆地比例等于设定值。
  2. 陆地掩码整理：去掉不足 10 格的小岛、填平不与大洋相连的水域、对角相接的格子合并，反复直到稳定。
  3. 国家：按各块陆地面积分配种子（较大陆地先，种子用最远点采样分散），Dijkstra 生长，代价随坡度变大（国界倾向沿山脊），没有种子的小岛归最近的种子；之后 `no_corner_touches` 消除同一国家只在角点相接的格子（否则轮廓会自相接触）。
  4. 轮廓：每个国家（或无国家时每块陆地）的格子追踪成逆时针外环与顺时针洞，**保留全部格点**（某处的直线中点可能是另一侧两国的交点，共享边界必须逐点一致——这是调试中发现的问题），由 `build` 建成共享边拓扑；再对每条边去掉直线中点（`straightened`）、Chaikin 平滑三次（节点不动，相交则保持原样），最后 `refine_borders` 加分形细节（30 km，粗糙度可调）。
  5. 国家名称与城市名（`names`，按风格）、自动配色、每国首都（国土内点，设为首都）；河流：从海岸向内的优先洪泛（填平洼地），累计汇水面积，从最大的河口沿主流上溯，平滑后作为有名称、显示名称的河流。
  6. 可选**随机历史**：`testworld::random_history`（从测试世界生成器中抽出的同一段逻辑，测试世界的结果不变）——边界移动、分裂建国（用名称池起名，失败的尝试也用掉一个名字，避免重名）、国家终止与继承、海岸变化；之后重新自动配色（各年相邻都不同色）。
- **地形**（`map_core::terrain::Terrain`，`Document.terrain`，以 `Arc` 共享，撤销副本不复制；serde 默认无，保存时没有就不写）：高程网格（米），`at` 双线性取值，`shade` 生成晕渲图（西北光照；按陆地 95% 分位坡度自动定夸张比例，阴坡暗、阳坡亮、海上透明），`georef` 给出全球等距圆柱的配准。`Style.hillshade`（默认 0.6）为强度。
- **应用**：晕渲图作为"在陆地之上"的参考图层画在两个视图中（复用参考图的 GPU 路径；地形变化时重算一次）；"样式"标签有地形时出现"地形晕渲"强度与"删除地形"（可撤销）。"文件"菜单"新世界向导…"窗口（`map_app::wizard_ui`）：名称、星球半径、陆地比例、大陆数、粗糙度、国家数（0 为只生成陆地）、名称风格、河流数、首都、随机历史（起止年与变化次数）、种子（可随机）；后台生成，完成后作为新的未保存文档打开，状态栏报告结果；当前文档有未保存修改时先询问"放弃修改并生成"。
- **导出**：`Scene.shade`（按导出投影逐像素反投影取样晕渲图，乘以强度），PNG 画在面之上、线之下；SVG 嵌入为 PNG 数据（`<image id="hill-shading">`，自带 base64）；PDF 为带 `/SMask` 透明度的图像对象。

**测试**：全部 287 项测试通过。新增 `map_core/tests/worldgen.rs` 4 项（有效拓扑、陆地比例 ±0.07、国家覆盖全部陆地且名称不重复、相邻国家不同色、首都在本国、河流下坡且河口近海、陆地不到地图边缘与两极；同种子同结果、不同种子不同；无国家时只有无主陆地；随机历史：变化次数与年份范围、历史之前的国家数、各年相邻不同色、名称不重复）、`map_core::terrain` 单元测试（取值、晕渲明暗与海上透明）、`map_io/tests/terrain.rs` 2 项（保存读回地形；晕渲进入场景、PNG、SVG、PDF，关闭与无地形时没有）、`svg` 的 base64 测试。

**界面实测**：向导默认设置生成（含随机历史）1.7 s：陆地 32%、11 块陆地、24 国、12 条河、24 座城、115 次历史变化；不含历史 0.4 s。两个视图中：自然海岸与分形国界、带名称的河流沿山谷、首都、国名；修正前晕渲看不见（真实坡度在半度网格上太小），改为按分位坡度自动夸张后山体明暗清楚。导出古典图集主题的 PNG（1600 × 860）检查过：晕渲、海岸晕带、河流、弯曲国名、图例都正确。

**限制**：地形只来自向导（没有地形画笔与导入）；网格为半度，放大很多时晕渲变得粗糙；晕渲与矢量海岸略有错位（网格与平滑后的海岸不完全一致）；随机历史中的海岸变化不改变地形；生成的陆地不跨日界线、不覆盖两极。

## M9 第二步——事件时间线与编年表（2026-11-16）

## M8 第二步——PDF 导出、视图上的比例尺与指北针、导出范围预览（2026-11-16）

**做了什么**

- **PDF 导出**（`map_io::pdf::render(scene, font)`）：与 PNG、SVG 用同一个导出场景，写成一页矢量 PDF（图片的 1 像素 = 0.75 pt，即 96 dpi）。面用偶奇填充、线有圆角端点与虚线、半透明用 `ExtGState`（`/GSn gs`）、城市点为贝塞尔圆。**文字写成字形轮廓**：按标注所名的字体（`map_io::fonts::load`）、否则默认中文字体、再否则符号字体，取字形轮廓（`ttf_parser` 的 `OutlineBuilder`，二次曲线换成三次）、按字体的实际宽度居中、按标注角度绕中心旋转、斜体为错切；光晕是同一轮廓的描边（颜色按 `halo_for`），粗体而字体没有粗体字形时略加描边。所以 PDF 不嵌入字体，任何阅读器与打印机看到的都一样。海岸色带用 `W* n` 裁剪到海洋。图例（白底框、色块、线与符号、文字）与标题同 SVG 的布局（`legend_layout`）。页面内容用 zlib 压缩（新依赖 `miniz_oxide` 0.8，已在依赖树中，离线可编译）；文档信息里写标题（UTF-16）。
- 导出窗口的格式多了"PDF"；逐年导出、地图集、版式都可以用 PDF；`atlas-query` 的 `preview.render` 接受 `.pdf`，并如实报告格式（原来非 PNG 一律报 svg）。
- **视图上的比例尺与指北针**（`map_app::furniture_ui`）：两个视图左下角，比例尺按视图中心 100 像素量出的公里数取 1/2/5×10ⁿ，四段黑白；视图横跨超过 8000 公里时注明"图中心"；指北针指向视图中心处北方在屏幕上的方向（球面上随旋转变化）。"视图"菜单"比例尺与指北针"开关，记在偏好设置里（`Prefs::furniture`，默认开）。
- **导出范围预览**：导出窗口打开且投影、中央经线与平面图相同时，在平面图上用橙色虚线画出导出图片的范围（按导出时的适配方式），并标出像素尺寸。

**测试**：全部 274 项测试通过。新增 `map_io/tests/pdf.rs` 2 项：文件结构（头、尾、交叉引用表中每个对象的偏移都指向该对象、内容流可解压），面与线的数量，y 轴翻转与 0.75 的比例，页面尺寸；有系统字体时文字为字形轮廓且每个标注至少一次填充；海岸色带被裁剪、透明度用图形状态、没有默认字体时文件仍完整。

**实测**：`atlas-query` 导出示例世界为 PDF（71 KB），在内置浏览器的 PDF 查看器中打开：地图、弯曲的国家名称与光晕、图例都正确，标题栏显示文档标题；放大后字形轮廓清晰。应用中：两个视图左下角显示比例尺（平面图"5000 km 图中心"，球面"2000 km"）与指北针；打开导出窗口时平面图上出现 3000 × 1600 的导出范围框。

**限制**：PDF 中的文字不能选择或搜索（是轮廓）；没有书签与多页（地图集为多个文件）；比例尺与指北针只在视图上，导出时仍由导出窗口的选项决定；导出范围预览只在投影相同时显示。

## M8 第一步——地图主题（2026-11-16）

**做了什么**

- **主题是样式的集合**（`map_core::basemap`）：`THEMES` 四套——现代（默认外观）、古典图集（柔和的国家颜色、褐色国界、沿海蓝色晕带、宋体名称）、羊皮纸（黄褐纸面、棕色线条与文字、楷体名称）、深色（暗色海洋、浅色线条与文字）。`MapTheme::apply` 只改外观（海洋、陆地、湖泊、海岸、国界、内部边界、河流的颜色与线宽、标注颜色、字体、色调、海岸晕带），保留显示开关与叠加分区层；`matches`/`current` 判断当前样式是否就是某个主题（字体除外）。主题的字体是一张候选表，界面取本机有的第一个。
- **新的样式项**（`Style`，serde 默认，旧工程外观不变）：`tone`/`tone_mix`——政治地图上国家颜色与图例向色调靠拢（`Style::toned`，在 `theme::evaluate_with` 中应用）；`coast_glow`/`coast_glow_width`——沿海岸在海中由深到浅的三道色带（`Style::glow_bands`，宽度为 2W、4W/3、2W/3 像素）。`doc::halo_for(颜色)`：深色文字配白色光晕，浅色文字配近黑光晕。
- **应用内绘制**：海岸色带用三个新的 GPU 线类别（`tess::class::GLOW`，线类别 9–11）；`tess::glow_lines` 从线块中取出海岸线段，按宽到窄排列；`App::glow` 在线块重建或开关变化时重算。GPU 绘制顺序改为：海洋 → 下层参考图 → **海岸色带** → 面 → 上层参考图 → 线，所以陆地盖住色带内侧一半。色带在球面上只画在球的轮廓以内（片元着色器按屏幕距离与 `GlobeCamera::disc_px` 比较，半径放在 `light.w`），在平面图上离地图左右边缘不到一个色带宽的线段不画（避免伸出地图）。国家名称的光晕、城市名称随标注颜色变化（深色主题为浅色文字）。
- **导出**：`Scene.glow`；PNG 与 SVG 在第一块面（海洋）之后、其余面之前画色带，并裁剪到海洋的轮廓（PNG 用 `tiny_skia::Mask`，SVG 用 `clipPath`）。文字光晕按 `halo_for`（SVG 对浅色文字单独写 `stroke`）；城市名称在深色主题下用标注颜色。
- **界面**："样式"标签的"样式"段顶部四张主题卡片（小图：海洋、色带、两国的色调、国界、主题名在其标注颜色中），单击即应用（一步撤销）；已改动时显示"（自定义）"。表格中新增"国家颜色色调"（颜色与比例）和"海岸晕带"（颜色与宽度）。

**测试**：全部 272 项测试通过。`map_core::basemap` 单元测试（应用、识别、保留显示开关、改动后不再识别、深色主题的暗光晕）；`map_io/tests/themes.rs` 4 项（默认主题无色带；色带由宽到窄、三种宽度、在海洋之后陆地之前、改变图片；色调改变国家颜色与图例；深色主题的浅色文字与暗光晕）。图像回归测试不变（默认外观未变）。

**界面实测**（示例世界）：四个主题依次应用，两个视图都正确（古典图集：柔和颜色、蓝色晕带、宋体；羊皮纸：黄褐、棕色晕带、楷体；深色：暗海、浅色名称与暗光晕、浅色城市名）。发现并修正：宽色带在球面边缘伸出球外、在平面图左右边缘伸出地图——改为在着色器中按球的轮廓裁剪、在平面图边缘附近不画。

**限制**：色带只在海洋中可见（湖泊的面画在色带之上）；色带是固定像素宽，不随缩放变化；经纬网颜色不随主题变化；主题不改变线路、区域等要素的样式。

## M7 第九步——收尾：填充桶、按属性选择、智能吸附、局部视图的后续（2026-11-16）

**做了什么**

**测试**：全部 267 项测试通过。新增 `map_core/tests/fill.rs` 2 项（一国的一片交给另一国、其他不变、可撤销；两国的地变无主后成为一片、按年份生效、水域不能填充）、`map_core/tests/query.rs` 1 项（每种条件分别与组合）、`map_core::snap` 单元测试 2 项（点优先于对齐、纬度与经纬网、跨日界线）。压力测试新增第 21 类操作。

## M7 第八步：局部视图（2026-11-15，简要）

目标：对于战争等局部变化，不通过图层，而用一个独立的办法实现局部查看。

- `map_core::focus`：`Document.focuses`（serde 默认）——名称、地区（西南东北，可跨日界线）、可选的起止年份。`faces_in`（中点在地区内的面）、`shown_owner`、`changed_between`、`change_years_of`、`change_report`/`focus_report`（各国面积变化、易手土地、海陆变化）。
- 界面 `map_app::focus_ui`："视图"菜单"新建局部视图"（平面图当前视野 + 当前年份起十年）、"局部视图"子菜单、"退出局部视图"。进入后：两个视图移到该地区（跨地图边缘时移动中央经线）；时间轴只走这几年，"上一/下一变化"只看这一地区；区域外的陆地变淡；自起始年以来易手的土地用红线（新的 GPU 线类别 `class::FOCUS`，线类别上限 8→12）标出；地区边界为红色虚线并标名称。浮动窗口：改名、年份、"设为当前视野"、变化摘要、播放/暂停、回到范围、删除、退出。修改都可撤销。
